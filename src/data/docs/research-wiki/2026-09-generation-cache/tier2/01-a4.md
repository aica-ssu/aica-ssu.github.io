## 1. Research Questions

**P4 지위:** A4는 S2 history retention을 뒷받침할 첫 causal diagnosis다. 독립 accepted paper나 새 refresh algorithm으로 확정하지 않는다. 문서 작성자는 P3 점수를 변경하지 않으며 채택·명명·venue는 사용자 결정이다.

Primary RQ는 긴 reuse 후 같은 full-compute budget에서 history 유지와 제한된 rebuild의 후속 prediction error가 다른가이다.
먼저 같은 schedule의 history-only effect를 식별하고, 그 뒤 history를 고정한 schedule 배치 효과를 식별한다.
S2로 전달할 것은 유리한 burst 이름이 아니라 prefix를 버린 뒤 언제 어느 정도의 추가 update가 필요해지는지의 조건이다.

- **two-sentence pitch:** Video diffusion의 Taylor predictor는 refresh 후에도 이전 derivative를 읽으므로 retained history가 후속 예측에 영향을 줄 수 있다. 동일 입력·schedule에서 history만 조작하여 그 영향과 재구성 비용을 분리하고 S2 retention 판단에 필요한 관측을 만든다.

Frontmatter의 assumed 성공 기준은 기존 P2 anchor를 보존한 목표이며 결과 예측이 아니다.

작은 pilot로 마지막 기준을 통계적으로 입증할 수 없으므로 causal sign screening과 paper-level confirmation을 구분한다.
모든 measured 성능·quality·fit 결과는 unknown이다.

**Falsifiable predictions:** 동일 schedule에서 history effect가 사라지는 경우, fixed low-order가 지배하는 경우, burst 효과가 단순 full-call 위치로 설명되는 경우다.
이때 S2에 복구 비용이 중요하다는 전제를 전달하지 않는다. 음성 결과와 사용자 결정 필요성을 기록한다.

## 4. Mechanism

### A4-M-1

#### 동작 원리

**Toolbox Attribution:** Taylor forecasting/reuse의 extension인 진단 개입이다. Warmup, finite differences, fixed schedule을 새 알고리즘으로 주장하지 않는다.

### Mechanism Summary Table

| 구성 | 개입 대상 | 유지하는 것 | 실제 출력 | 반증 |
|---|---|---|---|---|
| history-only | self.taylor_factors의 contiguous prefix | current_step, context, sigma, schedule | 같은 schedule의 prediction/quality 차이 | fixed low-order와 차이 없음 |
| clear-on-entry | full update 직전 previous factors 전체 | clock와 request 의미 | 새 feature부터 자라는 history | clear가 매번 발생해 성장 못 함 |
| schedule placement | eligible full-call mask | 총 full-call 수·prefix policy | isolated/burst 차이 | fixed schedule가 지배 |
| debt accounting | 예정 update와 필요한 update 차이 | source recurrence | module update 수와 실제 추가 cost 분리 | 추가 비용 없음 |

Stock recurrence는 새 feature를 order zero로 만들고 이전 order j가 존재하는 동안만 j+1을 만든다.
Analytic prefix 0..r, configured order p에서 k exact updates 후 available order는 min(p,r+k)다.
Analytic 전체 order-key 복구에는 max(0,p-r) exact **module update calls**가 필요하다.
이는 이미 예정된 refresh가 수행할 수 있으므로 추가 full-model call 수가 아니다.
Analytic deadline 이전 m개의 eligible 예정 update가 있으면 부족 update 하한은 max(0,p-r-m)이다.
동일 model call에서 여러 module이 갱신될 수 있으므로 module별 부족 수를 합산해 NFE라고 쓰지 않는다.

Clean-new history는 별개의 개입이다. 모든 previous factors를 버린 뒤 analytic p+1 fresh exact observations로 최고 order p를 만든다.
Retain-prefix 회복은 old observation 의존성을 남길 수 있으며 order-key 복구가 full-history arm과 수치 일치를 뜻하지 않는다.
Source는 nonzero delta_step만 요구한다. Consecutive burst가 필요하거나 항상 유리하다는 보장은 없다.
짧은 간격은 차분 잡음을 키울 수 있고, 이 recurrence를 비균일 sigma의 exact Newton interpolation으로 바꿔 부르지 않는다.

```diff
+    should_compute = self.recovery_plan.full_at(self.state_manager.context, state.current_step)
 if should_compute:
     outputs = self.fn_ref.original_forward(*args, **kwargs)
     wrapped_outputs = (outputs,) if isinstance(outputs, torch.Tensor) else outputs
+    if self.recovery_plan is not None:
+        action = self.recovery_plan.consume_entry(self.state_manager.context, state.current_step)
+        apply_history_action(state, action)
     state.update(wrapped_outputs)
     return outputs
```

`recovery_plan`, `consume_entry`, `apply_history_action`는 proposed symbol이다. 생성자에서 default None을 넣고 `apply_taylorseer_cache`에서 module별 plan을 전달하도록 수정해야 한다.
Plan은 module/context별 immutable full-call mask와 once-only entry event를 가진다. Request cleanup에서 소비 기록도 지운다.
`_measure_should_compute`를 매 호출 정확히 한 번 호출하여 stock context별 current_step 증가를 보존한다.
Plan mask는 warmup·초기화·cooldown을 포함한 완전한 mask이며 stock modulo 결과와 OR하지 않는다. 그렇지 않으면 total count가 바뀐다.
Prefix-truncate event를 다음 predict 전에 적용하려면 앞선 full-update 직후 경계로 정의하거나 explicit pre-predict boundary에만 둔다. 본 pilot는 full-update 직전으로 고정한다.

```python
# Proposed, design-only helper. Mutates the actual history read by update/predict.
def apply_history_action(state, action):
    if action is None or action.kind == "keep":
        return
    assert not state.is_inactive  # skip/zero modules excluded from this pilot
    if action.kind == "clean_new":
        state.taylor_factors = {}  # once at full-update entry, never before predict
        # Keep last_update_step until the immediately following stock update.
    elif action.kind == "prefix":
        r = action.retained_order
        assert r >= 0 and state.taylor_factors
        for factors in state.taylor_factors.values():
            assert set(range(r + 1)).issubset(factors)
        state.taylor_factors = {
            i: {j: factors[j] for j in range(r + 1)}
            for i, factors in state.taylor_factors.items()
        }
    else:
        raise ValueError(action.kind)
```

Clean-new에서 old last_update_step을 잠시 보존해도 previous factors가 비었으므로 recurrence가 즉시 break하고 fresh order zero만 저장한다.
바로 이어지는 stock `state.update`가 `last_update_step=current_step`으로 정상 갱신한다. empty state가 predict로 넘어가면 오류다.
Repeated same-step update는 stock delta_step 오류를 내므로 helper가 clock를 만들어내거나 retry로 감추지 않는다.
중간 개입에서는 `state.reset()`/`StateManager.reset()`을 호출하지 않는다. sampling 완료 후 request cleanup에는 기존 reset을 유지한다.
Sigma/timestep/step_index/context name은 CacheContext에서 읽기만 하며 source factor 좌표는 current_step 차이를 그대로 사용한다.
외부 scheduler의 sigma 배열, latent, conditioning epoch를 변경하지 않는다. Callback 편집은 이 pilot 범위 밖이다.
`predict`는 output zero의 factor 개수를 모든 tuple output에 적용하므로 동일 prefix 길이와 연속 key를 모든 output에 강제한다.
Tuple arity·dtype·device와 full/predicted output wrapping을 원본대로 유지한다. conditional/unconditional context state를 합치지 않는다.

#### 검증 시나리오

Design-only unit 조건은 tensor fixture에서 prefix keys, tuple degree 일치, once-only clear, monotone clock, request cleanup, context 독립성을 검사하는 것이다.
Cache-disabled와 plan=None 경로는 동일 initial latent 및 backend에서 기존 pipeline 결과와 사전 등록 tolerance 이내여야 한다.
Active module을 full-forward한 직후 state에 실제 저장한 factor와 다음 predict가 읽는 factor의 object/key provenance를 대조한다.
logging-only prototype은 개입 완료가 아니다. New/old dictionary가 함께 살아 있는 transient bytes도 S4 accounting에 포함한다.
Source logical contract는 검토했지만 build·tensor test·GPU execution은 하지 않았으므로 runtime correctness는 unknown이다.

### (4) 실험 요소: 도구와 metric 예산

초기 latent는 request별 저장·재사용하며 random generator 소비 순서에만 의존하지 않는다.
Per-step audit에는 request/module/context, current_step, scheduler step_index/timestep/sigma, last_update_step, available prefix, full mask, elapsed time을 기록한다.

Motion/identity는 고정 metric 구현과 manual failure label을 함께 기록하되 소표본에서 percentage-point 비열등성을 확정하지 않는다.

Metric runtime·peak도 생성과 별도로 기록하여 metric 때문에 GPU cap을 넘는지 확인한다.

Prefix 0..r retain은 clean-new와 별도 calibration 진단이며 두 arm을 같은 이름으로 합치지 않는다.

Schedule entry와 burst length는 calibration에서 선택하고 heldout prompt 또는 미래 feature를 보고 변경하지 않는다.
Reference full trajectory는 offline 비교 전용이다. 정책 입력으로 test quality·버린 고차 factor·미래 exact feature를 공급하지 않는다.

## 7. 관련 연구 · 차별점

| 선행 | 이미 하는 일 | A4 비교에서 남길 질문 |

Abs의 제목·도메인·abstract를 P4에서 확인했다. TaylorSeer/BudCache/GP-Refiner의 accepted venue는 저자 metadata이고 다른 paper의 peer-reviewed 상태를 추정하지 않는다.
Nearest implementation의 동일 Wan checkpoint 지원, full-text arm 중복, 공식 code parity는 unknown이다. Name만 넣었다고 baseline 구현 완료가 아니다.
배포 구현 확인: pinned diffusers에 max_order, dtype, Lite 설정 및 reset이 이미 있다. 이런 knobs 또는 재warmup의 존재는 새 기여가 아니다.
GP-Refiner의 trajectory 문제정의와 BudCache의 equal-budget schedule 최적화를 인정하므로 A4 자체의 독립 신규성을 주장하지 않는다.
S2와 결합해도 신규성은 자동 생기지 않는다. Classical cost-aware retention 대비 debt의 실제 필요성을 실증해야 한다.

## 8. 리스크 · 한계

실제 workload에서 retained history가 도움되는지, contamination이 해로운지, burst가 낫는지는 모두 unknown이다.
Old prefix는 같은 semantic epoch 안에서는 유효한 정보일 수 있다. 오래됐다는 이유만으로 corruption이라고 부르지 않는다.
반대로 discarded 고차 factors를 새 lower-order factors에 임의 접합하면 기준 시점이 섞인다. 이 동작은 admissible retention action이 아니다.
S2에 전달하는 것은 stock recurrence가 허용하는 상태 전이와 measured 필요 항목이다. Offline shadow-history는 실험 분석용이며 online cost에서 숨기지 않는다.
형식 scope band나 문서 길이·검사 통과는 novelty·impact 점수와 무관하다. T2는 S2 지원 지위를 표현하는 후보 표기다.
보조 진단이 양성이어도 기존 GP correction, fixed schedule, fixed low-order 대비 잔차가 없으면 독립 방법 주장은 지지되지 않는다.

### P4 Problem-first · self-check · up/down/sideways trace

**Retrospective disclosure:** 아래 trace는 기존 P2와 P3 리뷰 후 재구성한 P4 판단이다. 최초 ideation이 problem-first였다는 사후 증거로 꾸미지 않는다.
Problem-first: cache policy를 먼저 더하는 대신 source에 실제 남는 history가 미래 prediction을 바꾸는지 질문한다.
Self-check: p-r를 extra NFE로 착각하지 않았는가, reset으로 clock를 바꾸지 않았는가, equal count와 equal latency를 섞지 않았는가를 점검했다.
Up: 큰 주장은 memory-constrained history retention의 quality/time 선택이다. A4 단독으로 이 주장을 입증하지 않는다.
Down: actual factor dictionary, context clock, tuple prefix, full-mask count까지 내려가 개입을 고정한다.
Sideways: GP correction, DiCache alignment, BudCache schedule, SenCache sensitivity 및 low-order를 대안 원인으로 둔다.
남은 결정: S2 지원 진단 채택 또는 학습용 negative-result 보존은 사용자 몫이다. 문서 수정만으로 점수를 올리지 않는다.


### Source integration 사전 조건 — calibrated review 후 국소 보완

- 이 문서의 TaylorSeer baseline/policy 비교는 default hook regex에 맡기지 않는다. Pinned 구현은 `re.fullmatch`를 쓰므로 실제 CogVideoX `attn1`과 Wan `attn1/attn2`는 기본 `.*attn` 패턴에 매치되지 않는다.
- 최초 pilot의 동일 hook set은 self-attention만이다. `cache_identifiers=[r"transformer_blocks\.\d+\.attn1"]`(CogVideoX), `[r"blocks\.\d+\.attn1"]`(Wan), `use_lite_mode=False`, `skip_predict_identifiers=[]`를 명시한다. FFN/cross-attention은 별도 확대이며 기본 pilot의 cacheable compute 비중을 과장하지 않는다.

## 9. 약어 glossary

- CFG — Classifier-Free Guidance; context별 conditional/unconditional 출력을 조합하는 방식.
- DiT — Diffusion Transformer; iterative denoising network.
- NFE — Number of Function Evaluations; 어떤 함수·scope를 센 것인지 명시해야 하는 호출 수.
- LPIPS — Learned Perceptual Image Patch Similarity; reference 영상과의 perceptual fidelity 지표.
- PSNR — Peak Signal-to-Noise Ratio; reference와의 pixel reconstruction 지표.
- VAE — Variational Autoencoder; latent와 decoded frame을 변환하는 부분.
- RNG — Random Number Generator; 같은 initial latent 재사용을 대체하지 않는 난수 장치.
- E2E — End-to-End; denoising뿐 아니라 decode와 실제 정책 비용을 포함한 경로.
- Prefix — 여기서는 order zero부터 연속으로 남긴 Taylor factor 집합.
- Debt — 예정 refresh로 충당되지 않는 recovery 작업의 비용; 실제 추가 time은 measured 필요.
