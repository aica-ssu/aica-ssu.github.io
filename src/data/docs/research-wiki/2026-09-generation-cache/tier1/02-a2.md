## 1. Research Questions

같은 평균 paired fidelity와 latency 조건에서 cache 정책 순위가 motion·occlusion·identity failure tail에서 재현 가능하게 뒤집히는가?

- **two-sentence pitch:** Video generation caching에서 최종 평균 reconstruction similarity는 짧은 identity switch나 멈춘 동작을 희석할 수 있다. 동일 초기 latent를 사용하는 paired trajectory audit와 응용 실패 구간별 ranking 분석를 검증하여 적용 경계를 밝힌다.

- Success metric은 assumed 사전 성공 기준: 평균 LPIPS 차이 ≤0.01와 latency 차이 ≤5%인 operating point에서 사전 정의 failure rate 차이 ≥10 percentage points, held-out model family에서 방향 재현이다. 모든 목표는 assumed 사전 기준이며 projected 결과값을 뜻하지 않는다.

**Falsifiable predictions:**

- Matched fidelity에서 분해된 quality 순위가 항상 일치한다.
- 역전이 작은 sample 또는 metric noise에서만 나타나 held-out prompt에서 사라진다.
- Motion 감소를 제외하면 tail 차이가 사라진다.

## 4. Mechanism

### A2-M-1

#### 동작 원리

동일 초기 latent를 사용하는 paired trajectory audit와 응용 실패 구간별 ranking 분석.

1. CogVideoXPipeline.__call__에서 초기 latent와 step별 policy decision을 run-ID에 연결한다. Profile 실행과 timing 실행을 분리한다.
2. Full trajectory와 cached trajectory를 동일 초기 latent에서 별도로 생성하는 계획을 세운다. 같은 step의 local error와 final fidelity를 따로 저장한다.
3. VBench의 identity, flicker, dynamic-degree와 동작 요구 prompt를 함께 사용한다. motion이 감소해 flicker만 좋아진 경우를 성공으로 세지 않는다.
4. Calibration에서 matched-fidelity operating point를 정하고 held-out prompt category별 failure rate와 policy ranking을 paired bootstrap한다. Post-hoc 불리한 사례만 선택하지 않는다.

- Toolbox Attribution: 기존 speculative prediction/reuse 정책을 평가 대상으로 사용한다. Taylor forecasting과 cache schedule은 기존 기여이며 A2가 이를 개선했다고 주장하지 않는다. 새 score의 명명이나 기존 VBench 표의 반복도 기여로 계산하지 않는다.

- 위 diff의 plan/audit/adapter는 proposed symbol이다. 이미 존재하는 API라고 주장하지 않는다. Caller ripple은 pipeline→transformer→cache hook→state 경로이며 tuple output과 conditional branch ordering을 보존해야 한다.

#### Trace 공급자와 as-is → to-be 계약

외부 코드 anchor는 다음처럼 고정한다. 아래 source symbol은 모두 local clone에서 직접 열었으며, `audit`, `event_context`, `module_key`는 작성할 proposed symbol이다.

| anchor | as-is (verbatim) | to-be | change | 확인 범위 |

+ # proposed: log the existing decision; do not recompute it

- `_measure_should_compute()`는 counter를 증가시키므로 logger가 관찰 목적으로 재호출하면 정책을 바꾼다. 위 반환값을 재사용하고 audit가 cache state를 수정하지 않도록 한다. 등록 caller가 module name을 알고 있으므로 `_apply_taylorseer_cache_hook` 및 hook constructor에 logger identity를 전달하는 patch가 필요하다. 현재 API에 그 인자가 이미 있다는 뜻이 아니다.

- Run-level key는 `(family, checkpoint_revision, prompt_id, seed_id, initial_latent_hash, policy_id, setting_id, run_id)`이다. Step event는 여기에 `(pipeline_step, scheduler_timestep, transformer_identity, cache_context, module_key, hook_step, invocation_id)`를 더한다. Cache state 내부 counter와 pipeline step이 같다고 가정하지 않으며 각각 기록한다. 최종 영상·semantic label은 run-level key에 붙인다.

- CogVideoX의 `noise_pred.float()` 직후 tensor는 CFG 이전이며 `cond_uncond` batch의 unconditional/conditional 순서를 metadata로 기록한다. Guided prediction은 guidance 조합 뒤 별도 stage label을 붙인다. Wan은 `cond`와 `uncond` 호출을 별도로 기록하고 두 호출을 같은 raw tensor로 취급하지 않는다. Callback 기본 입력은 post-step `latents`이므로 pre-CFG prediction을 callback이 자동 제공한다고 가정하지 않는다.

- 두 독립 trajectory의 같은 timestep prediction 차이는 입력 latent도 달라진 **trajectory divergence**다. Cache approximation의 local error라고 해석하려면 audit 전용으로 동일 입력 latent에서 exact oracle을 평가해야 하며, 이 추가 계산은 timing headline에서 제외하고 audit 비용으로 따로 센다. 처음 pilot은 final video와 scalar decision을 우선하고 full activation 저장·oracle 재실행은 원인 분해가 필요할 때만 사용한다. 전체 tensor history를 GPU에 유지하지 않는다.

#### 검증 시나리오

- Design-only unit: cache disabled 결과와 wrapper pass-through 결과를 동일 initial latent에서 비교한다. State의 reset boundary, dtype, tuple output을 검사한다. Mechanism-isolated 비교에서는 schedule을 먼저 고정하여 representation과 decision feedback을 분리한다. GPU 실험은 수행하지 않았다.

## 6. Full implementation 전략 (E3)

실험 7-요소 계획이며 design-only이다.

- (1) 환경: 사용자 확인 single GPU 24–32GB workstation. GPU SKU·CPU/RAM·driver는 unknown. Wan2.1-T2V-1.3B와 CogVideoX-2b부터 capacity를 확인하며 모든 arm의 offload/precision을 동일하게 고정한다. Multi-GPU는 요구하지 않는다.

(2) 모델: Wan2.1-T2V-1.3B primary, CogVideoX-2b secondary. Exact checkpoint revision과 compatibility smoke는 unknown이며 사용자 실행 준비에서 고정한다. Training은 포함하지 않는다.

- (3) 데이터: calibration과 held-out prompt를 생성 전 분리한다. motion, occlusion, identity, static category의 정의·prompt 목록·semantic rubric을 먼저 고정한다. 공통 설계의 단계적 실행 원칙을 따르되 이 후보의 작은 pilot가 우선이다. **assumed pilot 예산은 primary family의 전체 12 prompts × 1 seed × 3 methods = analytic 36 generation calls**이며 timing 재실행은 별도다. 세 방법은 no-cache reference, 기존 공개 cache 정책, 가장 단순한 fixed-refresh 대조군이다. 여기서 12개는 category당 개수가 아닌 총수다. 새로운 candidate controller arm을 만들지 않는다.

- Pilot의 목적은 wrapper/hook 정상 동작, semantic label 작성 가능성, matching 가능성을 반증하는 것이다. 작은 pilot에서 극단 tail 확률이나 통계적 확신을 주장하지 않는다. 본 연구로 진행할 경우 assumed calibration 전체 8 prompts × 2 seeds와 held-out 전체 24 prompts × 2 seeds를 기존 초안대로 사용하며, pilot와 서로 다른 prompt로 구성한다. 이 개수 역시 screening 설계이며 검정력 보장이 아니다. 실제 run time과 실패 빈도를 본 뒤 확대 규모는 연구자가 별도 등록한다. 다른 seed만 사용한 같은 prompt를 held-out prompt로 세지 않는다.

- (4) 도구: pinned diffusers, CUDA events, torch.cuda.max_memory_allocated/max_memory_reserved, unique tensor storage inventory. Nsight Systems는 attribution run에만 쓰고 timing run과 분리한다. Framework 코드 확인만 수행했으며 의존성 설치/모델 실행은 하지 않았다.

- (5) 비교·ablation: 작은 pilot에서는 위의 **assumed 3 methods**만 사용한다. 공개 cache는 pinned TaylorSeer의 같은 self-attention hook set에서 시작할 수 있다. 단순 fixed-refresh 대조군은 동일 hook set에서 last-value reuse를 쓰는 기준으로 정의하며, 기존 forecasting predictor와 구별한다. 양쪽 설정이 실제로 같아지면 같은 방법을 이름만 달리해 독립 비교로 세지 않는다. AdaCache 등 최근 직접 경쟁은 primary 결과가 남고 공식 구현·checkpoint 호환성이 확인된 뒤 필요한 비교로 제한한다. 새로운 controller를 구현하는 것이 A2의 완료 조건은 아니다.

### Quality-loss tail과 의미 실패의 운영 정의

평가 단위는 **prompt–seed pair**다. 같은 pair의 no-cache 영상과 모든 policy 영상을 같은 initial latent에서 비교한다. No-cache 영상도 의미적으로 틀릴 수 있으므로 ground truth로 취급하지 않는다.

| 항목 | 정의·방향 | 해석 제한 |
|---|---|---|
| Paired fidelity loss | frame별 LPIPS를 영상 내 평균한 `L[p,s,m]`; 클수록 reference와 더 다름 | 텍스트 의미 정답 점수가 아님 |
| Quality-loss tail | nonnegative `L`의 상위 분위 또는 사전 tolerance를 넘는 비율; 클수록 나쁨 | 작은 pilot의 최고값을 population tail quantile로 부르지 않음 |
| High-is-good quality의 손실 | `D=max(0, Q_reference-Q_policy)`; 상위 tail이 악화 | signed 차이도 별도 보고해 개선·손실을 상쇄하지 않음 |
| Semantic failure | prompt가 요구한 동작 미수행, 가려짐 뒤 대상 정체성 불연속, 대상 소실 등 사전 rubric 위반 | VBench 단독 판정 금지; motion/flicker 지표는 보조 증거 |
| Cache-induced failure | no-cache가 rubric을 통과한 pair에서 policy만 실패 | 전체 failure rate와 조건부 rate의 분모를 각각 공개 |

- 문서의 **failure rate 차이 assumed ≥10 percentage points**는 frozen semantic failure indicator의 정책 간 비율 차이다. LPIPS의 증가량이나 VBench dimension 평균을 그 비율로 대체하지 않는다. `rate_A-rate_B > 0`이면 A가 더 나쁘다. 순위 역전은 calibration의 평균 fidelity/resource 기준이 선호한 정책이 held-out semantic failure에서 더 나쁜 경우로 정의하며, 기준 점수가 동률이면 역전 대신 평균 지표의 **구별 불능**으로 보고한다. 기존 RQ의 역전 가설은 이 구분을 통과해야 한다.

- Motion-required prompt의 정지 영상이 flicker/smoothness 점수에서 좋아져도 동작 미수행이면 실패다. Dynamic-degree가 낮다는 사실만으로 모든 static prompt를 실패로 판정하지도 않는다. VBench는 분해된 diagnostic일 뿐 semantic ground truth가 아니다. Prompt·영상의 method label을 가린 rubric review를 사용하고, 자동 지표와 사람이 불일치하면 양쪽을 보존한다. 판정 불가능한 occlusion/identity 사례는 `unknown`으로 기록한다. Policy별 unknown 개수를 공개하고 unknown을 모두 성공/모두 실패로 둔 sensitivity를 함께 보고하여 조용히 표본을 제외하지 않는다.

### Calibration, held-out와 통계 판정

- Calibration에서 모든 정책에 동일한 작은 사전 설정 목록과 비용 예산을 주고, 평균 LPIPS 차이 **assumed ≤0.01**, E2E latency 상대 차이 **assumed ≤5%**를 동시에 만족하는 operating-point pair를 선택한다. 상대 latency 차이는 `abs(T_A-T_B)/min(T_A,T_B)`로 고정한다. 같은 지점들이 여러 개면 사전 순서로 가장 빠른 feasible pair를 고르고, 동률은 평균 LPIPS와 고정 policy ID 순으로 해소한다. Held-out semantic label로 점이나 tolerance를 다시 선택하지 않는다.

- Feasible pair가 없으면 `matching infeasible`로 남기고 원래 RQ의 matched 조건에서 결과를 주장하지 않는다. Held-out에서 calibration matching이 깨지면 고정점의 frontier 차이로 보고하고 matched 비교의 성공으로 세지 않는다. 원본 실패율이 floor에 붙거나 모두 실패하는 ceiling이면 관찰 수와 분모를 그대로 남기고 RQ를 판별하지 못했다고 기록한다. 설정을 바꿔 성공 사례만 남기지 않는다.

- Bootstrap은 prompt를 cluster로 재표집하며 그 prompt의 모든 seed·정책 pair를 함께 이동시킨다. 같은 prompt의 seed, 영상의 frame, timing 반복을 독립 quality 표본으로 세지 않는다. category 균형 설계이면 category 안에서 prompt를 재표집하고 사전 가중치를 유지한다. **assumed 95% interval**은 full screening 분석의 보고 convention일 뿐 coverage·유의성 달성 주장이나 pilot의 수치 확신이 아니다. Seed 수가 제한되어 있으므로 seed 일반화 범위도 제한한다. Policy 간 평균·tail·실패율의 paired 차이와 per-prompt 원자료를 함께 공개한다.

- Timing은 assumed warm-up 1회 후 pair/arm당 3회 반복을 초기 설계로 둔다. 실행 순서를 교차하고 GPU 동기화를 포함한 E2E wall time과 denoiser/VAE breakdown을 기록한다. 반복 횟수는 latency 안정성 확인용이며 독립 영상 표본 증가가 아니다. 동일 반복 내 변동폭이 matching tolerance보다 크면 matching을 unresolved로 보고 추가 timing 여부를 정한다. Cache clear/reset은 각 요청에 적용한다. Audit run의 activation copy·oracle 비용은 별도 기록하고 latency run에서는 해당 계측을 비활성화한다.

- 자원 cap은 사용자 확인 **24–32GB 단일 GPU**다. 동일 precision/offload/backend/resolution/frame 설정에서 reference와 cache arm 모두 fit해야 한다. 한쪽만 줄여 fit시키지 않으며, OOM이면 모든 arm을 같은 작은 유효 shape로 재등록하거나 scope를 축소한다. Wan primary가 통과한 뒤 CogVideoX secondary를 순차 실행한다. Model revision·실제 peak bytes·GPU 시간은 아직 unknown이다. Calibration settings 수와 timing·oracle 추가 calls를 함께 적어 예상 GPU 시간을 산정하며 위 pilot 36 calls만 전체 비용으로 오해하지 않는다.

- Reproducibility: clone_spec은 frontmatter; environment unknown; build/smoke 미실행; patch list는 위 source anchor; cross-validation은 secondary family 또는 T2 동일 model의 held-out setting이다.

## 8. 리스크 · 한계

Measurement 논문으로 충분한 반복적 원인 설명이 필요하다. 나쁜 예시 모음, 한 모델의 metric rank 차이, 또는 기존 VBench 표 반복에 머물면 contribution이 약하다.

- Scope band는 WELL이다. 이는 family·mechanism·claim 수의 형식적 scope 판정이며 신규성이나 GPU feasibility 통과를 뜻하지 않는다. Candidate T1/T2는 문서 구성상의 후보이며 학회 acceptance 가능성 판단이 아니다. 사용자 확인 single GPU 24–32GB에서도 exact SKU와 모델별 fit 검증은 없으므로 실행 feasibility는 partial이다. 논문별 본문 전체와 공식 backend 구현이 동일 mechanism을 포함하는지는 추가 검증 대상이다.

가장 단순한 대안으로 효과가 재현되면 mechanism 주장을 축소한다. Negative result도 보존하고 성공한 prompt/seed만 선택하지 않는다.
