## 1. Research Questions

- two-sentence pitch: 더 풍부한 history는 forecasting을 돕지만 refresh 시 live state와 workspace를 늘린다. Taylor factor의 연속 prefix만 보존하면서 이미 예정된 exact update를 제외한 추가 재구성 비용을 추정하여 동일 memory cap 아래 retention을 결정한다.

Primary RQ-1: Predictor history의 추가 storage byte가 줄이는 refresh 시간을 추정하면, 고정 history 길이보다 동일 품질·physical memory 한도에서 빠른 실행을 얻을 수 있는가?

성공 기준: 동일 physical memory cap 및 품질 조건에서 E2E latency projected target ≥10% 감소. 모든 목표는 projected target이며 예상 성능의 예측값이 아니다. 현재 효과 크기는 unknown이다.

Falsifiable predictions / 반증 조건:

- history 추가 byte와 refresh 회피의 관계가 content 간 안정적이지 않으면 online estimator 가설을 기각한다
- 고정 짧은 history 또는 동일 예산 random allocation이 같은 frontier를 달성하면 가치 배분 주장을 기각한다
- probe 비용과 추가 refresh를 포함하면 E2E target에 못 미치는 경우 latency 주장을 기각한다

## 2. Problem Anchor

Problem: 더 풍부한 history는 forecasting을 돕지만 refresh 시 live state와 workspace를 늘린다. Bottleneck: state를 줄여 생기는 refresh 증가와 state 유지로 생기는 capacity/traffic 비용의 경쟁.

- Non-goals: 새 학습, multi-GPU platform, generic threshold sweep, DeepStack/VLA이다. Constraints: 학부생 범위, 사용자 확인 단일 GPU 24–32GB, 실행 예산과 exact settings fit unknown, 실험은 사용자 수행이다. Success condition: 동일 physical memory cap 및 품질 조건에서 E2E latency projected target ≥10% 감소.

예측 차수나 압축률을 sweep하는 제안이 아니다. state marginal value라는 원인 변수를 full refresh에서 검증한다. Full tensor를 보존해야만 counterfactual을 계산할 수 있으면 shadow history 비용을 반드시 budget에 포함하거나 탐색을 종료한다.

## 4. Mechanism

### M-1

#### 동작 원리

- **P4 semantic correction.** P2는 FasterCache의 fixed pair를 가변 history list로 바꾸려 했다. 실제 reader가 pair를 unpack하므로 그 patch는 계약 위반이다. P4에서는 같은 predictor-history memory/compute 문제를 TaylorSeer factor prefix로 구현한다. Problem Anchor와 RQ-1은 그대로이며 FasterCache 동작 보존이나 두 predictor의 동등성을 주장하지 않는다. 이 변경은 구현 의미 교정이며 새로운 사용자 방향·제목·venue 선택이 아니다.

- **Problem-first self-check (P4 retrospective).** 먼저 묻는 것은 한정된 GPU에서 history memory를 줄일 때 미래 refresh 비용이 증가하는가이다. 이미 낮은 차수/Lite/last-block으로 문제가 없어지면 allocator를 만들 이유가 없다. Source는 recurrence와 state availability만 증명하고 workload 병목은 증명하지 않는다. A1의 고정 배분과 A4의 clock 보존을 참고했지만 별도 성공으로 세지 않는다.

- **추상화 trace (P4에 수행).** Up: history memory→상태를 버리면 회복까지 관측이 필요한 자원배분 문제. Down: TaylorSeerState의 contiguous order keys, tuple output, update clock, storage alias로 제한. Sideways: ordinary cost-aware cache replacement와 비교하여 rebuild charge만 추가한 기존 정책과 동등한지 점검한다. 이는 P2에서 이미 수행한 과정으로 소급 기록하지 않는다.

- **State invariant.** 모듈 m, StateManager context c마다 available degree r와 configured maximum p를 분리한다. 각 tuple leaf의 keys는 동일한 연속 집합 {0,…,r}이다. 초기 empty만 예외이며 그때는 exact computation을 한다. inactive skip states는 후보에서 제외한다. 임의 sparse eviction·부분 leaf eviction은 허용하지 않는다. Request/CFG context 간 factor·clock·scalar estimator를 공유하지 않는다.

- **Recovery algebra (analytic).** retained prefix 0..r에서 stock recurrence는 exact update마다 최고 차수를 최대 하나 올린다. 유효한 clock과 nonzero delta_step, 동일 shape라는 전제에서 p 복원에 필요한 update는 max(0,p−r)이다. 이는 추가 full-model call 수가 아니다. 예정된 exact updates와 다른 모듈과 공유하는 calls를 빼야 한다. 과거 정보를 전부 버린 clean history에는 p+1 fresh exact samples가 필요하며 이는 별개의 실험이다. 연속 burst는 필요조건이 아니다.

- **Online estimator: computable but uncalibrated.** 결정은 예정된 exact-update 경계에서만 한다. update 전 남아 있는 factor로 degree q≤r마다 현재 step 예측을 계산하고, 같은 입력에서 나온 exact module output y와 normalized RMS residual e_q=RMS(y−pred_q)/(RMS(y)+epsilon)을 계산한다. epsilon은 dtype에 맞춰 calibration 때 고정한다. 이것은 cached trajectory의 local residual이며 full-reference trajectory 오차가 아니다. 계산 결과는 scalar만 남기고 tensor scratch를 즉시 해제한다. 해당 비용과 temporary peak를 계상한다.

- 동일 calibration prompt split에서 context·module·denoising phase별 EWMA residual과 threshold 초과 빈도 h_q, exact module time C_m, prefix storage byte B_q를 기록한다. 버린 차수 q>r에는 새 e_q를 만들 수 없다. 마지막 scalar의 age를 표시하고 calibration에서 고정한 validity horizon 이후에는 unknown으로 두어 static allocation으로 돌아간다. 미래 품질이나 evicted factor에 접근하지 않는다. shared module call에 대한 C_m을 full-model latency로 중복 합산하지 않는다.

- analytic policy surrogate: K_q=max(0,p−q); horizon 내 이미 예정된 해당 모듈 exact updates A_m을 빼서 D_q=max(0,K_q−A_m). 추가 rebuild charge R_q=D_q*C_m은 local upper-cost proxy이며 global-call union accounting으로 중복을 제거한다. H는 다음 policy decision까지 고정 horizon, h_q는 retained observation/calibration scalar이다. J_q=H*h_q*C_m+R_q+O_q를 예측 compute cost로 둔다. h_q가 실제 필요 refresh를 예측한다는 보장은 없다. calibration reliability가 실패하면 이 estimator를 폐기한다.

- 할당은 모든 모듈에 최소 prefix를 둔 뒤 feasible 한 차수 증가 중 (J_q−J_(q+1))/incremental_unique_bytes가 양수인 것을 greedy 선택한다. incremental bytes가 영이면 비율을 나누지 않고 non-worsening feasible 변경만 허용한다. 고차 증가는 즉시 materialize하지 않고 exact update가 실제 생성할 때만 available degree를 올린다. horizon은 cache interval에서 정하며 연속 knob 탐색은 하지 않는다. Myopic comparator는 같은 estimator에서 R_q만 제거한다. Ordinary cost-aware comparator는 같은 h_q, size, age, C_m을 쓰고 history를 generic refetch object로 취급한다. 그것이 같은 결정을 내리면 독자 기여는 없다.

- Memory cap은 factor 합이 아니다. current live unique backing storage, original outputs와 이전/new factors 동시 생존, prediction/probe scratch, denoiser workspace 및 decode peak를 포함한다. 현재 Tensor storage dedup로 B_q를 얻되 모듈 간 alias가 있으면 마지막 owner 제거 전에는 freed bytes로 세지 않는다. calibration workspace envelope가 실제 실행 중 초과되면 run을 cap-violation으로 중단·기록한다. 예정 eviction을 미래 free라고 미리 계산하지 않는다.

```python
from contextlib import contextmanager

@contextmanager
def bounded_order(state, target):
    original = state.max_order
    assert 0 <= target <= original
    state.max_order = target
    try:
        yield
    finally:
        state.max_order = original

def truncate_prefix(state, target):
    if state.is_inactive or not state.taylor_factors:
        return
    available = min(len(factors) - 1 for factors in state.taylor_factors.values())
    r = min(target, available)
    for factors in state.taylor_factors.values():
        assert set(range(available + 1)).issubset(factors)
        for order in list(factors):
            if order > r:
                del factors[order]
    # No reset: current_step, last_update_step, dtypes, device stay untouched.

def proposed_new_forward(self, module, *args, **kwargs):
    should_compute, state = self._measure_should_compute()  # once only
    if not self.policy.enabled or state.is_inactive:
        if should_compute:
            outputs = self.fn_ref.original_forward(*args, **kwargs)
            state.update((outputs,) if isinstance(outputs, torch.Tensor) else outputs)
            return outputs
        out = state.predict()
        return out[0] if len(out) == 1 else tuple(out)
    # No extra calls in causal arm. Adaptive arm permits same scalar gate to all methods.
    force = self.policy.force_exact(state) if self.policy.adaptive else False
    if should_compute or force or state.last_update_step is None:
        outputs = self.fn_ref.original_forward(*args, **kwargs)
        wrapped = (outputs,) if isinstance(outputs, torch.Tensor) else outputs
        self.policy.observe_retained(state, wrapped)
        target = self.policy.target_for(state)
        with bounded_order(state, target):
            state.update(wrapped)
        truncate_prefix(state, target)
        return outputs
    out = state.predict()  # original conversion and tuple convention
    return out[0] if len(out) == 1 else tuple(out)
```

- Unit synthetic 계획: scalar polynomial feature sequence로 tuple leaf마다 prefix 길이와 analytic rebuild count, nonzero delta, request reset을 확인한다. 입력/기대값은 독립적으로 계산; 실패하면 workload 실행 전 중지한다. 실행 예산은 assumed 작은 CPU correctness audit이며 이번 턴 미실행이다.

## 5. Quick-check (E1) 와 RQ revision 분기 (E2)

- `gain-check/S2-X-1.yaml`은 design-only analytic 손익식이다. avoided refresh fraction에서 policy/probe overhead, extra rebuild fraction, state traffic fraction을 차감한다. 가정 입력만 있으며 실제 sensitivity 실행도 하지 않았다. projected threshold ≥0.10은 채택 기준이고 예측치가 아니다. Recovery 식의 correctness와 workload gain을 분리한다.

- on_pass: RQ-1 유지: 실제 trace와 품질을 맞춘 full 검증으로 진행; band_move=none.
- on_below: RQ-1 축소: 이득이 존재하는 capacity 또는 execution regime로 한정; band_move=T1→T2.
- on_critical: RQ-1 재설정: 원인 가설이 기각되면 측정 메모로 보존하고 채택 보류; band_move=reposition.
- on_outperform: RQ-1 유지: 독립 family 검증 전에는 범위와 tier를 확대하지 않음; band_move=none.

Assumed analyst budget은 gain spec에 적힌 값이다. latency attribution에서 overhead+extra rebuild가 avoided work보다 크면 즉시 중단한다. E1 미실행이므로 branch 결과는 unknown이다.

## 7. 관련 연구 · 차별점

- From Reusing to Forecasting: Accelerating Diffusion Models with TaylorSeers — [arXiv:2503.06923](https://arxiv.org/abs/2503.06923). History로 feature를 forecasting하는 알고리즘 자체는 기존이다. 추가 state의 physical lifetime과 marginal value가 새 조건부 주장 후보일 뿐 우위는 unknown이다.
- DiCache: Let Diffusion Model Determine Its Own Cache — [arXiv:2508.17356](https://arxiv.org/abs/2508.17356). Sample별 probe와 trajectory alignment가 이미 존재한다. Sample adaptive cache라는 novelty는 배제하고 그 결정을 실행할 때의 비용만 독립 검증한다.
- Accelerating Diffusion Transformers with Gaussian Process Rectified Feature Cache — [arXiv:2609.05981](https://arxiv.org/abs/2609.05981). 원 evidence의 caching 정책/선택 기준은 기존 요소로 고정한다. 본 후보는 이를 새 알고리즘이라고 재명명하지 않으며 동일 budget/quality에서 비용을 비교한다.
- FasterCache: Training-Free Video Diffusion Model Acceleration with High Quality — [arXiv:2410.19355](https://arxiv.org/abs/2410.19355). 배포 baseline은 attention history와 CFG reuse를 제공한다. 이 구현의 수치 경로·quality를 유지하거나 변경 비용을 명시해야 하며 단순 cache 도입은 기여가 아니다.
- Xema: Efficient Diffusion Serving through Fine-Grained Memory Management and Auto-Configuration — [arXiv:2607.11136](https://arxiv.org/abs/2607.11136). Tensor lifetime, static layout, memory-pressure 구간별 완화와 serving planner를 이미 제공하며, E-217 fulltext에서 cross-step DiT cache와 VAE activation offload까지 다룬다. 따라서 cache-aware memory planning이라는 말만으로 차별화되지 않는다; 해당 dynamic history와 intervention이 planner로 표현되면 본 후보 기여는 소멸한다.
- FlexCache: Flexible Approximate Cache System for Video Diffusion — [arXiv:2501.04012](https://arxiv.org/abs/2501.04012). cache compression, object/background 분리와 replacement를 이미 결합한다. Storage 절감 일반론과 eviction은 신규 기여가 아니며 intra-request state의 추가 reader·refresh feedback이라는 차이도 본문 검증 전에는 주장하지 않는다.
- Beyond Few-Step Inference: Accelerating Video Diffusion Transformer Model Serving with Inter-Request Caching Reuse — [arXiv:2604.04451](https://arxiv.org/abs/2604.04451). Chorus의 inter-request latent/region reuse 및 semantic alignment와 경쟁 범위를 분리한다. 요청 간 cache hit를 이용한 속도는 본 후보의 단일 요청 state 최적화 이득으로 이전할 수 없다; cold trace도 비교해야 한다.

- 가장 가까운 경쟁자 목록은 위 verified sources이며 실존 확인과 contribution 차별성 확인은 구별한다. P0 source 기록 및 이번 abs fetch로 title/abstract를 확인했다. 관련 최신 preprint를 제거해 published 비율을 맞추지 않았다. 초기 System pool의 published 비율은 analytic 7/15≈46.7%로 required 65% 미달이었다. 본문 workload 보강 후 전체 mix 재계산은 root의 최종 pool gate 대상이며 본 후보의 venue eligibility는 unknown이다. Venue 후보는 provisional로 사용자 결정 전 확정하지 않는다.

- Forecasting When to Forecast: Accelerating Diffusion Models with Confidence-Gated Taylor — [arXiv:2508.02240](https://arxiv.org/abs/2508.02240). CG-Taylor는 module-level history를 last-block으로 바꾸고 confidence gating을 결합하여 memory를 줄인다. Memory 감소와 confidence gating 자체는 기존이며 S2는 이 강한 단순 baseline을 반드시 넘어야 한다.

- LightCache: Memory-Efficient, Training-Free Acceleration for Video Generation — [arXiv:2510.05367](https://arxiv.org/abs/2510.05367). LightCache가 encoding/denoising/decoding을 나누고 asynchronous cache swapping, feature chunk, sliced decode를 이미 제공한다. 따라서 phase-aware working set이나 offload로 memory peak를 낮춘다는 주장 자체는 신규성이 없다. Exact-history ownership 전환의 추가 이득 또는 dynamic refresh의 독립 잔차가 이 baseline 뒤에도 남아야 한다.

- FreqCa: Accelerating Diffusion Models via Frequency-Aware Caching — [arXiv:2510.08669](https://arxiv.org/abs/2510.08669). FreqCa는 Cumulative Residual Feature를 저장해 all-layer state를 줄이고 frequency별 reuse/prediction을 결합한다. S2의 필수 memory-strong comparator이며 cache memory와 total allocated memory를 구별한다. Image-domain 근거이므로 video 적용 성공은 unknown이고 applicability를 확인하지 않고 수치만 비교하지 않는다.

## 8. 리스크 · 한계

예측 차수나 압축률을 sweep하는 제안이 아니다. state marginal value라는 원인 변수를 full refresh에서 검증한다. Full tensor를 보존해야만 counterfactual을 계산할 수 있으면 shadow history 비용을 반드시 budget에 포함하거나 탐색을 종료한다.

Scope tier는 provisional이다. Full experiment 예산은 frontmatter의 assumed analyst planning 수치이며 GPU 가용성을 보장하지 않는다. Family portability가 없으면 primary RQ의 적용 범위를 좁히고 tier를 재평가한다.

- Claim/anti-claim map: C-1의 anti-claim은 가장 단순한 baseline이 동일 frontier를 얻거나 부가 비용이 이득을 소거한다는 것이다. Full 실험 X-2의 decisive 비교로 판정한다. 학부생에게는 구현 hook이 존재하는 장점과 baseline reproduction/quality 평가 비용이 크다는 부담이 함께 있다.

일반 memory planning, cache policy 조합, 단순 free 수정의 신규성은 인정하지 않는다. Fresh scoop와 독립 kill-argument는 상위 orchestration 단계에 남아 있으므로 이 문서는 최종 선정이 아니다.

- 가용 prefix key 복원은 factor 값이나 quality 복원이 아니다. 비균일 sampling에서 stock recurrence를 exact Newton divided differences로 부르지 않는다. recovery가 기존 scheduled calls로 충족되거나 ordinary policy/hysteresis가 같은 frontier를 얻으면 novelty와 추가 latency 이득은 기각한다. Logical 계약 보완 이후에도 empirical feasibility·quality·novelty는 unknown이며 P3 raw uncalibrated 평점은 이 writer가 바꾸지 않으며 fresh calibrated review가 별도로 평가한다. 실험 전이라는 사실만으로 점수 상한이나 rejection을 정하지 않는다.


### Source integration 사전 조건 — calibrated review 후 국소 보완

- 이 문서의 TaylorSeer baseline/policy 비교는 default hook regex에 맡기지 않는다. Pinned 구현은 `re.fullmatch`를 쓰므로 실제 CogVideoX `attn1`과 Wan `attn1/attn2`는 기본 `.*attn` 패턴에 매치되지 않는다.
- 최초 pilot의 동일 hook set은 self-attention만이다. `cache_identifiers=[r"transformer_blocks\.\d+\.attn1"]`(CogVideoX), `[r"blocks\.\d+\.attn1"]`(Wan), `use_lite_mode=False`, `skip_predict_identifiers=[]`를 명시한다. FFN/cross-attention은 별도 확대이며 기본 pilot의 cacheable compute 비중을 과장하지 않는다.
- Student smoke의 완료 조건은 `named_modules()` matching path 목록·등록 hook 수>0·정확 update/재사용 branch 둘 다 실제로 호출됨이다. 등록 0건은 speedup 결과가 아니라 configuration failure다. 이 세션은 source+regex 확인만 했으며 runtime 결과는 unknown이다.
- Lite는 custom patterns를 override하므로 별도 baseline arm이다. Scalar policy 비교는 동일 hook set으로, CG-Taylor/Lite처럼 granularity가 다른 기법은 동일 quality·total memory로 비교한다.
- 실제 등록 함수는 `src/diffusers/hooks/taylorseer_cache.py :: def _apply_taylorseer_cache_hook() @ fbf49e7f35857f76bc57b177e26f12b03687c668`이고 기존 인자는 `(module, config, is_inactive)`다. 새 module key/policy를 넣는 변경은 기존 인자가 있다고 가장하지 않고 caller와 signature 양쪽 변경으로 설계한다.
- Static 확인 근거는 `ledger/hook-route-static-probe.json`이며 full model inference 검증을 대체하지 않는다. 이 보완은 research mechanism의 효과나 novelty를 올리는 근거가 아니다.
