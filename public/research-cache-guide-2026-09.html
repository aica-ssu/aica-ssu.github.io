1. 한 줄 요약 · 이 idea 가 하는 일

영상 생성의 지난 계산 기록을 얼마나 남겨야 덜 기다리는지 알아본다.

  • ViT에서 생성 모델로 — ViT의 attention과 MLP를 읽는 경험을 가져오되, 생성에서는 잡음이 섞인 내부 표현을 같은 네트워크에 반복 입력한다는 차이를 먼저 이해하자. 반복 단계와 네트워크의 깊이, 영상 속 시간은 서로 다른 축이다.
  • Diffusion의 반복 — 각 단계에서 모델이 잡음을 줄이는 데 필요한 값을 예측하고, scheduler가 내부 표현을 갱신하며, 마지막에 decoder가 영상을 만든다. 앞 단계의 작은 근사 오차도 뒤 입력을 바꿀 수 있으므로 중간 값이 비슷하다는 사실만으로 안전한 생략을 보장하지 못한다.
  • 계산 기록으로 예측하기 — TaylorSeer는 과거 중간 특징과 변화율을 저장해 다음 특징을 예측한다. 기록은 숫자 하나짜리 메모가 아니라 특징 크기의 tensor들이므로, 차수와 저장 대상이 늘면 GPU 메모리와 읽기·쓰기 비용도 늘어난다.
  • 기록을 버리는 대가 — 최신 특징만 남기면 저장량은 줄지만, 버린 변화율을 다시 만드는 데 여러 정확한 관측이 필요할 수 있다. 다만 원래 예정된 계산이 관측을 제공하면 추가 비용 없이 복구될 수도 있다.
  • 이번 연구의 범위 — 사용자가 확인한 단일 GPU의 assumed 자원 범위는 24–32GB이며 실제 설정의 적재 가능 여부는 unknown이다. 모델 가중치뿐 아니라 저장 기록, 계산 중 임시 공간, 영상 복원 공간까지 같은 메모리 한도 안에서 비교한다.
  • 현재 판단 — 제안 단계의 Accept는 시험할 가치가 있다는 뜻이며 성능 검증이나 논문 채택을 뜻하지 않는다. 최종 검증 경고는 WARN으로 남아 있고, measured 성능 이득은 unknown이다.
  • M-1 연속된 기록만 남기기 — 계산 노트의 뒤쪽부터 지우듯, 최신 특징부터 변화율까지 이어진 Taylor factor의 앞부분만 보존한다. 중간 차수만 뽑아 지우지 않고 같은 모듈 출력의 모든 구성 tensor에 같은 차수 범위를 적용한다.
  • M-1 복구 비용을 세고 보존량 정하기 — 지운 노트를 다시 쓰는 노력에서 원래 할 숙제를 빼듯, 예정된 정확 계산이 채워 줄 기록을 먼저 차감한다. 남은 추가 비용을 절약할 가능성이 큰 기록에 저장 공간을 배정한다는 것이 검증할 가설이다.
  • 차수와 호출은 다르다 — analytic 관계로, 목표 차수 p와 남은 차수 r 사이의 복구에는 max(0,p−r)번의 해당 모듈 exact update가 필요하다. 이 수는 추가 전체 모델 호출 수가 아니며, 예정 update와 여러 모듈이 함께 쓰는 호출을 중복 계산하면 안 된다.
  • 기본 설정의 반례 — observed source 기본값은 p=1이고, assumed 조건 r=0과 예정 update A=1에서는 analytic 추가 복구량 max(0,1−0−1)=0이다. 기본 저차 설정에서는 이 복구 비용을 고려하는 이득이 없을 수 있다는 WARN을 첫 시험에서 반드시 확인한다.
  • 기록의 가치를 관측하기 — 원래 정확히 계산할 때 남아 있는 기록의 예측과 실제 모듈 출력을 비교하고 오차·시간·바이트를 기록한다. 버린 tensor를 몰래 보관해서 효과를 추정하지 않으며, 관측이 오래되어 믿기 어려우면 고정 배분으로 돌아간다.
  • 실제 메모리 계산 — 같은 저장 공간을 공유하는 tensor는 중복해서 더하지 않고, 마지막 소유자가 없어져야 해제된 것으로 센다. 새 factor를 만들 때 이전 factor와 동시에 살아 있는 공간, 예측 임시 공간, 정책 계산과 데이터 이동 비용도 포함한다.

3. Research Question

  • S2 RQ-1(원문): "Predictor history의 추가 storage byte가 줄이는 refresh 시간을 추정하면, 고정 history 길이보다 동일 품질·physical memory 한도에서 빠른 실행을 얻을 수 있는가?"
  • 쉬운 말로 — 같은 크기의 책상에서 영상 품질을 지키면서, 다시 계산할 수고를 많이 덜어 주는 기록만 남기면 전체 기다림이 줄어들까? 저장 공간을 줄였다는 사실과 최종 실행시간이 줄었다는 사실은 따로 확인한다.
  • 속도 성공 기준 — 가장 강한 실행 가능한 비교법과 같은 품질·실제 메모리 한도에서 projected target 전체 실행시간 최소 10% 감소를 제안한다. 이 수치는 사전 채택 목표이며 measured 결과나 예상 이득의 예측값이 아니다.
  • 품질 비교 기준 — assumed 사전 판정 기준은 normalized 0–100 척도에서 VBench 전체 및 motion smoothness·temporal flicker·subject consistency 각각의 차이가 −1 percentage point 이상이며, paired 신뢰구간 하한도 이 기준을 넘어야 한다. 본 기준은 calibration 전에 동결할 제안이고 표본이 부족하면 결론은 unknown으로 남긴다.
  • 가장 강한 반론 — 고정 저차, Lite, last-block 방식이나 일반 cost-aware 배분이 같은 품질·메모리·시간 경계를 만들면 새로운 동적 정책의 기여는 지지되지 않는다. A4에서 기록의 인과 효과를 찾더라도 같은 호출 수가 같은 실행시간을 뜻하지 않는다.
  • 끝까지 더할 비용 — 정책 판단, 예측, 추가 재구성, 전송·offload, 영상 decode 시간을 전부 포함한다. 이 비용이 아낀 계산을 상쇄하면 속도 주장을 기각하고 결과가 잘 나온 설정만 골라 결론내리지 않는다.

4. Mechanism

M-1

동작 원리
  • P4 semantic correction. P2는 FasterCache의 fixed pair를 가변 history list로 바꾸려 했다. 실제 reader가 pair를 unpack하므로 그 patch는 계약 위반이다. P4에서는 같은 predictor-history memory/compute 문제를 TaylorSeer factor prefix로 구현한다. Problem Anchor와 RQ-1은 그대로이며 FasterCache 동작 보존이나 두 predictor의 동등성을 주장하지 않는다. 이 변경은 구현 의미 교정이며 새로운 사용자 방향·제목·venue 선택이 아니다.
  • Problem-first self-check (P4 retrospective). 먼저 묻는 것은 한정된 GPU에서 history memory를 줄일 때 미래 refresh 비용이 증가하는가이다. 이미 낮은 차수/Lite/last-block으로 문제가 없어지면 allocator를 만들 이유가 없다. Source는 recurrence와 state availability만 증명하고 workload 병목은 증명하지 않는다. A1의 고정 배분과 A4의 clock 보존을 참고했지만 별도 성공으로 세지 않는다.
  • 추상화 trace (P4에 수행). Up: history memory→상태를 버리면 회복까지 관측이 필요한 자원배분 문제. Down: TaylorSeerState의 contiguous order keys, tuple output, update clock, storage alias로 제한. Sideways: ordinary cost-aware cache replacement와 비교하여 rebuild charge만 추가한 기존 정책과 동등한지 점검한다. 이는 P2에서 이미 수행한 과정으로 소급 기록하지 않는다.
  • State invariant. 모듈 m, StateManager context c마다 available degree r와 configured maximum p를 분리한다. 각 tuple leaf의 keys는 동일한 연속 집합 {0,…,r}이다. 초기 empty만 예외이며 그때는 exact computation을 한다. inactive skip states는 후보에서 제외한다. 임의 sparse eviction·부분 leaf eviction은 허용하지 않는다. Request/CFG context 간 factor·clock·scalar estimator를 공유하지 않는다.
  • Recovery algebra (analytic). retained prefix 0..r에서 stock recurrence는 exact update마다 최고 차수를 최대 하나 올린다. 유효한 clock과 nonzero delta_step, 동일 shape라는 전제에서 p 복원에 필요한 update는 max(0,p−r)이다. 이는 추가 full-model call 수가 아니다. 예정된 exact updates와 다른 모듈과 공유하는 calls를 빼야 한다. 과거 정보를 전부 버린 clean history에는 p+1 fresh exact samples가 필요하며 이는 별개의 실험이다. 연속 burst는 필요조건이 아니다.
  • Online estimator: computable but uncalibrated. 결정은 예정된 exact-update 경계에서만 한다. update 전 남아 있는 factor로 degree q≤r마다 현재 step 예측을 계산하고, 같은 입력에서 나온 exact module output y와 normalized RMS residual e_q=RMS(y−pred_q)/(RMS(y)+epsilon)을 계산한다. epsilon은 dtype에 맞춰 calibration 때 고정한다. 이것은 cached trajectory의 local residual이며 full-reference trajectory 오차가 아니다. 계산 결과는 scalar만 남기고 tensor scratch를 즉시 해제한다. 해당 비용과 temporary peak를 계상한다.
  • 동일 calibration prompt split에서 context·module·denoising phase별 EWMA residual과 threshold 초과 빈도 h_q, exact module time C_m, prefix storage byte B_q를 기록한다. 버린 차수 q>r에는 새 e_q를 만들 수 없다. 마지막 scalar의 age를 표시하고 calibration에서 고정한 validity horizon 이후에는 unknown으로 두어 static allocation으로 돌아간다. 미래 품질이나 evicted factor에 접근하지 않는다. shared module call에 대한 C_m을 full-model latency로 중복 합산하지 않는다.
  • analytic policy surrogate: K_q=max(0,p−q); horizon 내 이미 예정된 해당 모듈 exact updates A_m을 빼서 D_q=max(0,K_q−A_m). 추가 rebuild charge R_q=D_q*C_m은 local upper-cost proxy이며 global-call union accounting으로 중복을 제거한다. H는 다음 policy decision까지 고정 horizon, h_q는 retained observation/calibration scalar이다. J_q=H*h_q*C_m+R_q+O_q를 예측 compute cost로 둔다. h_q가 실제 필요 refresh를 예측한다는 보장은 없다. calibration reliability가 실패하면 이 estimator를 폐기한다.
  • 할당은 모든 모듈에 최소 prefix를 둔 뒤 feasible 한 차수 증가 중 (J_q−J_(q+1))/incremental_unique_bytes가 양수인 것을 greedy 선택한다. incremental bytes가 영이면 비율을 나누지 않고 non-worsening feasible 변경만 허용한다. 고차 증가는 즉시 materialize하지 않고 exact update가 실제 생성할 때만 available degree를 올린다. horizon은 cache interval에서 정하며 연속 knob 탐색은 하지 않는다. Myopic comparator는 같은 estimator에서 R_q만 제거한다. Ordinary cost-aware comparator는 같은 h_q, size, age, C_m을 쓰고 history를 generic refetch object로 취급한다. 그것이 같은 결정을 내리면 독자 기여는 없다.
  • Memory cap은 factor 합이 아니다. current live unique backing storage, original outputs와 이전/new factors 동시 생존, prediction/probe scratch, denoiser workspace 및 decode peak를 포함한다. 현재 Tensor storage dedup로 B_q를 얻되 모듈 간 alias가 있으면 마지막 owner 제거 전에는 freed bytes로 세지 않는다. calibration workspace envelope가 실제 실행 중 초과되면 run을 cap-violation으로 중단·기록한다. 예정 eviction을 미래 free라고 미리 계산하지 않는다.

@contextmanager
def bounded_order(state, target):
    original = state.max_order
    assert 0 <= target <= original
    state.max_order = target
    try:
        yield
    finally:
        state.max_order = original

        return

        for order in list(factors):

7. 관련 연구 · 차별점

  • From Reusing to Forecasting: Accelerating Diffusion Models with TaylorSeers — arXiv:2503.06923. History로 feature를 forecasting하는 알고리즘 자체는 기존이다. 추가 state의 physical lifetime과 marginal value가 새 조건부 주장 후보일 뿐 우위는 unknown이다.
  • DiCache: Let Diffusion Model Determine Its Own Cache — arXiv:2508.17356. Sample별 probe와 trajectory alignment가 이미 존재한다. Sample adaptive cache라는 novelty는 배제하고 그 결정을 실행할 때의 비용만 독립 검증한다.
  • Accelerating Diffusion Transformers with Gaussian Process Rectified Feature Cache — arXiv:2609.05981. 원 evidence의 caching 정책/선택 기준은 기존 요소로 고정한다. 본 후보는 이를 새 알고리즘이라고 재명명하지 않으며 동일 budget/quality에서 비용을 비교한다.
  • FasterCache: Training-Free Video Diffusion Model Acceleration with High Quality — arXiv:2410.19355. 배포 baseline은 attention history와 CFG reuse를 제공한다. 이 구현의 수치 경로·quality를 유지하거나 변경 비용을 명시해야 하며 단순 cache 도입은 기여가 아니다.
  • Xema: Efficient Diffusion Serving through Fine-Grained Memory Management and Auto-Configuration — arXiv:2607.11136. Tensor lifetime, static layout, memory-pressure 구간별 완화와 serving planner를 이미 제공하며, E-217 fulltext에서 cross-step DiT cache와 VAE activation offload까지 다룬다. 따라서 cache-aware memory planning이라는 말만으로 차별화되지 않는다; 해당 dynamic history와 intervention이 planner로 표현되면 본 후보 기여는 소멸한다.
  • FlexCache: Flexible Approximate Cache System for Video Diffusion — arXiv:2501.04012. cache compression, object/background 분리와 replacement를 이미 결합한다. Storage 절감 일반론과 eviction은 신규 기여가 아니며 intra-request state의 추가 reader·refresh feedback이라는 차이도 본문 검증 전에는 주장하지 않는다.
  • Beyond Few-Step Inference: Accelerating Video Diffusion Transformer Model Serving with Inter-Request Caching Reuse — arXiv:2604.04451. Chorus의 inter-request latent/region reuse 및 semantic alignment와 경쟁 범위를 분리한다. 요청 간 cache hit를 이용한 속도는 본 후보의 단일 요청 state 최적화 이득으로 이전할 수 없다; cold trace도 비교해야 한다.
  • 가장 가까운 경쟁자 목록은 위 verified sources이며 실존 확인과 contribution 차별성 확인은 구별한다. P0 source 기록 및 이번 abs fetch로 title/abstract를 확인했다. 관련 최신 preprint를 제거해 published 비율을 맞추지 않았다. 초기 System pool의 published 비율은 analytic 7/15≈46.7%로 required 65% 미달이었다. 본문 workload 보강 후 전체 mix 재계산은 root의 최종 pool gate 대상이며 본 후보의 venue eligibility는 unknown이다. Venue 후보는 provisional로 사용자 결정 전 확정하지 않는다.
  • Forecasting When to Forecast: Accelerating Diffusion Models with Confidence-Gated Taylor — arXiv:2508.02240. CG-Taylor는 module-level history를 last-block으로 바꾸고 confidence gating을 결합하여 memory를 줄인다. Memory 감소와 confidence gating 자체는 기존이며 S2는 이 강한 단순 baseline을 반드시 넘어야 한다.
  • LightCache: Memory-Efficient, Training-Free Acceleration for Video Generation — arXiv:2510.05367. LightCache가 encoding/denoising/decoding을 나누고 asynchronous cache swapping, feature chunk, sliced decode를 이미 제공한다. 따라서 phase-aware working set이나 offload로 memory peak를 낮춘다는 주장 자체는 신규성이 없다. Exact-history ownership 전환의 추가 이득 또는 dynamic refresh의 독립 잔차가 이 baseline 뒤에도 남아야 한다.
  • FreqCa: Accelerating Diffusion Models via Frequency-Aware Caching — arXiv:2510.08669. FreqCa는 Cumulative Residual Feature를 저장해 all-layer state를 줄이고 frequency별 reuse/prediction을 결합한다. S2의 필수 memory-strong comparator이며 cache memory와 total allocated memory를 구별한다. Image-domain 근거이므로 video 적용 성공은 unknown이고 applicability를 확인하지 않고 수치만 비교하지 않는다.

8. 리스크 · 한계

예측 차수나 압축률을 sweep하는 제안이 아니다. state marginal value라는 원인 변수를 full refresh에서 검증한다. Full tensor를 보존해야만 counterfactual을 계산할 수 있으면 shadow history 비용을 반드시 budget에 포함하거나 탐색을 종료한다.

Scope tier는 provisional이다. Full experiment 예산은 frontmatter의 assumed analyst planning 수치이며 GPU 가용성을 보장하지 않는다. Family portability가 없으면 primary RQ의 적용 범위를 좁히고 tier를 재평가한다.

  • Claim/anti-claim map: C-1의 anti-claim은 가장 단순한 baseline이 동일 frontier를 얻거나 부가 비용이 이득을 소거한다는 것이다. Full 실험 X-2의 decisive 비교로 판정한다. 학부생에게는 구현 hook이 존재하는 장점과 baseline reproduction/quality 평가 비용이 크다는 부담이 함께 있다.

일반 memory planning, cache policy 조합, 단순 free 수정의 신규성은 인정하지 않는다. Fresh scoop와 독립 kill-argument는 상위 orchestration 단계에 남아 있으므로 이 문서는 최종 선정이 아니다.

  • 가용 prefix key 복원은 factor 값이나 quality 복원이 아니다. 비균일 sampling에서 stock recurrence를 exact Newton divided differences로 부르지 않는다. recovery가 기존 scheduled calls로 충족되거나 ordinary policy/hysteresis가 같은 frontier를 얻으면 novelty와 추가 latency 이득은 기각한다. 1. 한 줄 요약 · 이 idea 가 하는 일

평균에 가려진 짧은 영상 오류를 보면 계산 방식의 선택도 달라지는지 살핀다.

  • 영상 생성 캐시는 반복 계산 중간의 값을 저장했다가 다시 쓰는 방법이다. 계산을 줄이는 대신, 재사용한 작은 오차가 이후 영상에 영향을 줄 수 있다.
  • 평균 유사도는 영상 전체가 기준 영상과 얼마나 닮았는지 압축해 보여 준다. 잠깐 사람이 바뀌거나 요구한 동작이 멈춰도 나머지 장면이 비슷하면 평균에서 희석될 수 있다는 것이 이번 가설이다.
  • 움직임과 정체성은 따로 봐야 한다. 사람이 가려졌다가 나타날 때 같은 사람인지, 달리라는 지시에 실제로 달리는지를 살피며, 정지해서 깜빡임이 줄어든 영상을 무조건 좋은 영상으로 판정하지 않는다.
  • 기존 평가와의 관계: VBench는 이미 품질을 여러 관점으로 나누며, CachedSearch는 캐시 때문에 탐색 후보의 순위가 달라지는 문제를 이미 연구한다. 캐시의 순위 오류나 움직임 평가의 약점 자체는 새로운 발견이 아니다.
  • 남은 질문과 경고: A2는 비슷한 평균 유사도와 실행시간을 가진 계산 정책 중 무엇을 고를지가 짧은 의미 오류를 보면 달라지는지 묻는다. 기존 연구와 겹치는 부분이 남아 있으며 현재 kill 판정은 WARN, 실제 역전과 독립 기여의 충분성은 unknown이다.
  • M-1 대응 영상 비교 — A2-M-1: 같은 출발선에서 달린 기록을 나란히 보듯, 같은 초기 잡음과 입력 문장으로 기존 캐시 정책들의 영상을 대응시킨다. 목표는 정책 선택이 달라지는 조건을 검증하는 측정 절차이며 새 가속 모델이나 새 품질 점수를 만드는 것이 아니다.
  • M-1 판정표 신뢰성부터: 채점자가 바뀌어도 답이 유지되는지 먼저 점검하듯, 방법 이름을 가린 동일 영상에 고정 판정표를 적용하고 반복 판정과 독립 판정을 비교한다. 불일치와 판정 불가를 정책에 가장 불리하게 배정해도 선택 차이가 남는지 살피며, 사전에 정한 안정성 기준이 없거나 충족되지 않으면 의미 실패 결론을 보류한다.
  • M-1 같은 조건 맞추기: 비슷한 가격의 물건을 비교하듯, 별도의 조정용 입력에서 평균 유사도와 실행시간이 비슷한 정책 설정을 고정한다. 이후 보지 않은 입력으로 비교하고, 맞는 설정이 없거나 새 입력에서 조건이 깨지면 맞춤 비교 성공으로 세지 않는다.
  • M-1 선택이 바뀌는지 보기: 평균만 본 선택과 동작·가려짐·정체성 실패까지 본 선택을 비교한다. 평균 기준이 동률이면 구별 불능으로 기록하고, 평균이 선호한 정책이 의미 실패에서는 더 나쁠 때만 순위 역전이라고 부른다.
  • 실패 분모 보존: 캐시를 끈 기준 영상도 의미적으로 틀릴 수 있어 정답으로 간주하지 않는다. 전체 실패율과 기준 영상이 성공했을 때 캐시만 실패한 비율을 따로 적고, 판정 불가 영상을 조용히 제외하지 않는다.
  • 기존 정책과 구현 범위: 캐시를 끈 기준, 공개 캐시 정책, 단순 고정 주기 재사용을 같은 계산 위치에서 비교하도록 설계한다. 기록 장치는 출력을 보존해야 하며, 계측을 켠 분석 실행과 실행시간 측정을 분리한다.
  • 비교의 한계: CachedSearch의 후보 선택은 생성된 영상들 중 어느 영상을 다시 계산할지 고르는 문제이고, A2의 정책 선택은 어느 재사용 방식을 쓸지 고르는 문제다. CachedSearch도 여러 캐시 방식과 움직임 평가 편향을 다루므로 이 구분만으로 신규성이 확보되지는 않으며, 움직임 감소만으로 설명되는 결과는 별개의 정체성 오류 원인으로 주장하지 않는다.

3. Research Question

  • A2 RQ-1(원문): "같은 평균 paired fidelity와 latency 조건에서 cache 정책 순위가 motion·occlusion·identity failure tail에서 재현 가능하게 뒤집히는가?"
  • 쉬운 말로: 전체 모습도 비슷하고 걸리는 시간도 비슷한 계산 방식들이, 짧은 동작 실패나 사람 바뀜까지 보면 서로 다른 추천을 받게 될까?
  • 사전 설계 목표 — assumed: 평균 LPIPS 차이 ≤0.01, 실행시간 상대 차이 ≤5%인 설정에서 의미 실패율 차이 ≥10 percentage points를 보고, 보지 않은 모델 계열에서도 방향을 재확인한다. 모두 assumed 설계 기준이며 달성한 결과나 예측 이득이 아니다.
  • 의미와 계산: LPIPS는 기준 영상과의 시각적 차이이고, 실패율은 미리 정의한 동작 미수행·대상 소실·정체성 불연속의 비율이다. 실행시간 맞춤 조건은 abs(T_A-T_B)/min(T_A,T_B)라는 analytic 정의를 사용하며 LPIPS나 VBench 평균을 의미 실패율로 대체하지 않는다.
  • 첫 반증: 라벨 반복·독립 판정의 불일치를 반영하면 선택 차이가 사라지거나, 보지 않은 입력에서 차이가 사라지면 핵심 주장을 지지하지 못한다. 표본 재추출로 얻는 구간도 채점 기준 자체의 체계적인 오류를 제거하지 못한다.
  • 작은 시작의 범위 — assumed: 초기 점검은 전체 12개 입력 × 1개 seed × 3개 방법으로 계획하며, analytic 계산으로 생성 36회다. 이는 기록·판정·조건 맞추기의 작동 가능성을 점검하는 assumed 예산으로, 희귀 오류의 빈도나 다른 모델로의 일반화를 입증하지 않으며 시간 반복·추가 조정 비용은 별도다.
  • 자원과 현재 상태: 사용자 제공 제약은 assumed 자원 조건인 24–32GB 단일 GPU이며 모델을 순차 점검하는 계획이다. 실제 적합 메모리·실행시간·성능 이득은 unknown이고, 모델 다운로드나 실험은 실행하지 않았다.

  • (1) 환경: 사용자 확인 single GPU 24–32GB workstation. GPU SKU·CPU/RAM·driver는 unknown. Wan2.1-T2V-1.3B와 CogVideoX-2b부터 capacity를 확인하며 모든 arm의 offload/precision을 동일하게 고정한다. Multi-GPU는 요구하지 않는다.

(2) 모델: Wan2.1-T2V-1.3B primary, CogVideoX-2b secondary. Exact checkpoint revision과 compatibility smoke는 unknown이며 사용자 실행 준비에서 고정한다. Training은 포함하지 않는다.

  • (3) 데이터: calibration과 held-out prompt를 생성 전 분리한다. motion, occlusion, identity, static category의 정의·prompt 목록·semantic rubric을 먼저 고정한다. 공통 설계의 단계적 실행 원칙을 따르되 이 후보의 작은 pilot가 우선이다. assumed pilot 예산은 primary family의 전체 12 prompts × 1 seed × 3 methods = analytic 36 generation calls이며 timing 재실행은 별도다. 세 방법은 no-cache reference, 기존 공개 cache 정책, 가장 단순한 fixed-refresh 대조군이다. 여기서 12개는 category당 개수가 아닌 총수다. 새로운 candidate controller arm을 만들지 않는다.
  • Pilot의 목적은 wrapper/hook 정상 동작, semantic label 작성 가능성, matching 가능성을 반증하는 것이다. 작은 pilot에서 극단 tail 확률이나 통계적 확신을 주장하지 않는다. 본 연구로 진행할 경우 assumed calibration 전체 8 prompts × 2 seeds와 held-out 전체 24 prompts × 2 seeds를 기존 초안대로 사용하며, pilot와 서로 다른 prompt로 구성한다. 이 개수 역시 screening 설계이며 검정력 보장이 아니다. 실제 run time과 실패 빈도를 본 뒤 확대 규모는 연구자가 별도 등록한다. 다른 seed만 사용한 같은 prompt를 held-out prompt로 세지 않는다.
  • (4) 도구: pinned diffusers, CUDA events, torch.cuda.max_memory_allocated/max_memory_reserved, unique tensor storage inventory. Nsight Systems는 attribution run에만 쓰고 timing run과 분리한다. Framework 코드 확인만 수행했으며 의존성 설치/모델 실행은 하지 않았다.
  • (5) 비교·ablation: 작은 pilot에서는 위의 assumed 3 methods만 사용한다. 공개 cache는 pinned TaylorSeer의 같은 self-attention hook set에서 시작할 수 있다. 단순 fixed-refresh 대조군은 동일 hook set에서 last-value reuse를 쓰는 기준으로 정의하며, 기존 forecasting predictor와 구별한다. 양쪽 설정이 실제로 같아지면 같은 방법을 이름만 달리해 독립 비교로 세지 않는다. AdaCache 등 최근 직접 경쟁은 primary 결과가 남고 공식 구현·checkpoint 호환성이 확인된 뒤 필요한 비교로 제한한다. 새로운 controller를 구현하는 것이 A2의 완료 조건은 아니다.

Quality-loss tail과 의미 실패의 운영 정의

평가 단위는 prompt–seed pair다. 같은 pair의 no-cache 영상과 모든 policy 영상을 같은 initial latent에서 비교한다. No-cache 영상도 의미적으로 틀릴 수 있으므로 ground truth로 취급하지 않는다.

Policy별 unknown 개수를 공개하고 unknown을 모두 성공/모두 실패로 둔 sensitivity를 함께 보고하여 조용히 표본을 제외하지 않는다.

Calibration, held-out와 통계 판정

  • Calibration에서 모든 정책에 동일한 작은 사전 설정 목록과 비용 예산을 주고, 평균 LPIPS 차이 assumed ≤0.01, E2E latency 상대 차이 assumed ≤5%를 동시에 만족하는 operating-point pair를 선택한다. 상대 latency 차이는 abs(T_A-T_B)/min(T_A,T_B)로 고정한다. 같은 지점들이 여러 개면 사전 순서로 가장 빠른 feasible pair를 고르고, 동률은 평균 LPIPS와 고정 policy ID 순으로 해소한다. Held-out semantic label로 점이나 tolerance를 다시 선택하지 않는다.
  • Feasible pair가 없으면 matching infeasible로 남기고 원래 RQ의 matched 조건에서 결과를 주장하지 않는다. Held-out에서 calibration matching이 깨지면 고정점의 frontier 차이로 보고하고 matched 비교의 성공으로 세지 않는다. 원본 실패율이 floor에 붙거나 모두 실패하는 ceiling이면 관찰 수와 분모를 그대로 남기고 RQ를 판별하지 못했다고 기록한다. 설정을 바꿔 성공 사례만 남기지 않는다.
  • Bootstrap은 prompt를 cluster로 재표집하며 그 prompt의 모든 seed·정책 pair를 함께 이동시킨다. 같은 prompt의 seed, 영상의 frame, timing 반복을 독립 quality 표본으로 세지 않는다. category 균형 설계이면 category 안에서 prompt를 재표집하고 사전 가중치를 유지한다. assumed 95% interval은 full screening 분석의 보고 convention일 뿐 coverage·유의성 달성 주장이나 pilot의 수치 확신이 아니다. Seed 수가 제한되어 있으므로 seed 일반화 범위도 제한한다. Policy 간 평균·tail·실패율의 paired 차이와 per-prompt 원자료를 함께 공개한다.
  • Timing은 assumed warm-up 1회 후 pair/arm당 3회 반복을 초기 설계로 둔다. 실행 순서를 교차하고 GPU 동기화를 포함한 E2E wall time과 denoiser/VAE breakdown을 기록한다. 반복 횟수는 latency 안정성 확인용이며 독립 영상 표본 증가가 아니다. 동일 반복 내 변동폭이 matching tolerance보다 크면 matching을 unresolved로 보고 추가 timing 여부를 정한다. Cache clear/reset은 각 요청에 적용한다. Audit run의 activation copy·oracle 비용은 별도 기록하고 latency run에서는 해당 계측을 비활성화한다.
  • 자원 cap은 사용자 확인 24–32GB 단일 GPU다. 동일 precision/offload/backend/resolution/frame 설정에서 reference와 cache arm 모두 fit해야 한다. 한쪽만 줄여 fit시키지 않으며, OOM이면 모든 arm을 같은 작은 유효 shape로 재등록하거나 scope를 축소한다. Wan primary가 통과한 뒤 CogVideoX secondary를 순차 실행한다. Model revision·실제 peak bytes·GPU 시간은 아직 unknown이다. Calibration settings 수와 timing·oracle 추가 calls를 함께 적어 예상 GPU 시간을 산정하며 위 pilot 36 calls만 전체 비용으로 오해하지 않는다.
  • Reproducibility: clone_spec은 frontmatter; environment unknown; build/smoke 미실행; patch list는 위 source anchor; cross-validation은 secondary family 또는 T2 동일 model의 held-out setting이다.

1. 한 줄 요약 · 이 idea 가 하는 일

다시 계산한 뒤에도 옛 기억이 답을 흐리는지 비교한다.

  • ViT에서 이어지는 배경 — 이미 아는 Transformer block을 생성 모델에서는 서로 다른 noise 수준의 입력에 반복 적용한다; 이때 저장한 중간 feature로 계산을 대신하면 현재 입력 자체가 조금씩 달라질 수 있다.
  • TaylorSeer의 기억은 최근 feature뿐 아니라 그 변화량을 포함하므로, 새 feature를 정확히 계산한 뒤에도 이전 변화량이 다음 예측에 쓰인다. 오래된 기억이 실제로 얼마나 해로운지는 unknown이다.
  • 현재 입력에서 정확한 재계산은 길을 잘못 든 현재 위치에서 지도를 다시 읽는 것과 같다; 처음부터 정확히 계산한 경로로 되돌아가는 rollback이 아니며, 앞서 달라진 latent가 그대로 남는다.
  • A4의 지위는 S2가 이력을 보존해야 하는 이유를 시험하는 선행 진단·ablation이다. 기존 kill 판정의 PASS는 이 지원 범위에 대한 공격 해소이며 독립 accepted method, S2 성능 입증 또는 별개의 추가 논문을 뜻하지 않는다.
  • M-1 / A4-M-1 이력만 바꾸는 비교 — 같은 길목에서 옛 메모를 보관한 경우와 비운 경우를 비교한다; 동일한 current latent와 full-call schedule에서 keep, 연속 prefix 일부 보존, clear-on-entry를 나누어 history-only effect를 먼저 살핀다.
  • 별도로 보는 계산 배치 — 총 공부량이 같아도 몰아서 하는지 나눠 하는지가 다른 문제인 것처럼, history 정책을 고정하고 같은 총 full-call 수의 isolated와 burst 배치를 비교한다. 총 호출 수만 같고 위치가 다른 비교를 이력 삭제의 효과라고 해석하지 않는다.
  • clear-on-entry의 범위 — 지정된 full update 직전에 previous factors만 한 번 비우며 step clock, scheduler 위치, request/context를 보존한다. 매번 비우면 고차 이력이 자라지 못하고, trajectory 중간에 전체 reset_state를 호출하면 clock까지 바뀌어 비교가 무너질 수 있다.
  • 복구 계산법 — 최고 차수 p에서 연속 prefix 0..r을 남기면 필요한 order-key 복구는 analytic max(0,p-r) module updates다. 이미 예정된 갱신 m회가 deadline 전에 있다면 부족 갱신 하한은 analytic max(0,p-r-m)이며 이것이 곧 추가 full-model 비용은 아니다.
  • 새 이력과 다른 점 — 전부 비운 clean-new history는 최고 차수 p까지 analytic p+1 fresh observations가 필요하다. Prefix 복구는 옛 관측 의존성을 남길 수 있으므로 key가 다시 생겼다는 사실을 깨끗한 이력이나 원래 경로로의 복원이라고 부르지 않는다.

3. Research Question

  • A4 RQ-1(원문): "긴 reuse 뒤 full refresh에서 과거 derivative history를 유지하는 것보다 제한된 history rebuild가 같은 총 full-compute budget에서 후속 prediction error를 줄이는가?"

  • 판정 전에 고정할 것 — paired no-cache 기준 영상에 대한 fidelity와 이후 prediction residual을 분리하고 LPIPS excess의 기준·분모를 사전 명시한다. 초기 latent, prompt, context, 호출 mask를 짝지으며 denominator가 미미하면 상대 감소율만으로 성공을 판정하지 않는다.

8. 리스크 · scoop · kill

실제 workload에서 retained history가 도움되는지, contamination이 해로운지, burst가 낫는지는 모두 unknown이다. Old prefix는 같은 semantic epoch 안에서는 유효한 정보일 수 있다. 오래됐다는 이유만으로 corruption이라고 부르지 않는다. 반대로 discarded 고차 factors를 새 lower-order factors에 임의 접합하면 기준 시점이 섞인다. 이 동작은 admissible retention action이 아니다. S2에 전달하는 것은 stock recurrence가 허용하는 상태 전이와 measured 필요 항목이다. Offline shadow-history는 실험 분석용이며 online cost에서 숨기지 않는다. 형식 scope band나 문서 길이·검사 통과는 novelty·impact 점수와 무관하다. T2는 S2 지원 지위를 표현하는 후보 표기다. 보조 진단이 양성이어도 기존 GP correction, fixed schedule, fixed low-order 대비 잔차가 없으면 독립 방법 주장은 지지되지 않는다.

P4 Problem-first · self-check · up/down/sideways trace

Retrospective disclosure: 아래 trace는 기존 P2와 P3 리뷰 후 재구성한 P4 판단이다. 최초 ideation이 problem-first였다는 사후 증거로 꾸미지 않는다. Problem-first: cache policy를 먼저 더하는 대신 source에 실제 남는 history가 미래 prediction을 바꾸는지 질문한다. Self-check: p-r를 extra NFE로 착각하지 않았는가, reset으로 clock를 바꾸지 않았는가, equal count와 equal latency를 섞지 않았는가를 점검했다. Up: 큰 주장은 memory-constrained history retention의 quality/time 선택이다. A4 단독으로 이 주장을 입증하지 않는다. Down: actual factor dictionary, context clock, tuple prefix, full-mask count까지 내려가 개입을 고정한다. Sideways: GP correction, DiCache alignment, BudCache schedule, SenCache sensitivity 및 low-order를 대안 원인으로 둔다. 남은 결정: S2 지원 진단 채택 또는 학습용 negative-result 보존은 사용자 몫이다. 문서 수정만으로 점수를 올리지 않는다.

Stock recurrence는 새 feature를 order zero로 만들고 이전 order j가 존재하는 동안만 j+1을 만든다. Analytic prefix 0..r, configured order p에서 k exact updates 후 available order는 min(p,r+k)다. Analytic 전체 order-key 복구에는 max(0,p-r) exact module update calls가 필요하다. 이는 이미 예정된 refresh가 수행할 수 있으므로 추가 full-model call 수가 아니다. Analytic deadline 이전 m개의 eligible 예정 update가 있으면 부족 update 하한은 max(0,p-r-m)이다. 동일 model call에서 여러 module이 갱신될 수 있으므로 module별 부족 수를 합산해 NFE라고 쓰지 않는다.

Clean-new history는 별개의 개입이다. 모든 previous factors를 버린 뒤 analytic p+1 fresh exact observations로 최고 order p를 만든다. Retain-prefix 회복은 old observation 의존성을 남길 수 있으며 order-key 복구가 full-history arm과 수치 일치를 뜻하지 않는다. Source는 nonzero delta_step만 요구한다. Consecutive burst가 필요하거나 항상 유리하다는 보장은 없다. 짧은 간격은 차분 잡음을 키울 수 있고, 이 recurrence를 비균일 sigma의 exact Newton interpolation으로 바꿔 부르지 않는다.

# Proposed, design-only helper. Mutates the actual history read by update/predict.
def apply_history_action(state, action):
    if action is None or action.kind == "keep":
        return
    assert not state.is_inactive  # skip/zero modules excluded from this pilot
    if action.kind == "clean_new":
        state.taylor_factors = {}  # once at full-update entry, never before predict
        # Keep last_update_step until the immediately following stock update.
    elif action.kind == "prefix":
        r = action.retained_order
        assert r >= 0 and state.taylor_factors
        for factors in state.taylor_factors.values():
            assert set(range(r + 1)).issubset(factors)
        state.taylor_factors = {
            i: {j: factors[j] for j in range(r + 1)}
            for i, factors in state.taylor_factors.items()
        }
    else:
        raise ValueError(action.kind)

Clean-new에서 old last_update_step을 잠시 보존해도 previous factors가 비었으므로 recurrence가 즉시 break하고 fresh order zero만 저장한다. 바로 이어지는 stock state.update가 last_update_step=current_step으로 정상 갱신한다. empty state가 predict로 넘어가면 오류다. Repeated same-step update는 stock delta_step 오류를 내므로 helper가 clock를 만들어내거나 retry로 감추지 않는다. 중간 개입에서는 state.reset()/StateManager.reset()을 호출하지 않는다. sampling 완료 후 request cleanup에는 기존 reset을 유지한다. Sigma/timestep/step_index/context name은 CacheContext에서 읽기만 하며 source factor 좌표는 current_step 차이를 그대로 사용한다. 외부 scheduler의 sigma 배열, latent, conditioning epoch를 변경하지 않는다. Callback 편집은 이 pilot 범위 밖이다. predict는 output zero의 factor 개수를 모든 tuple output에 적용하므로 동일 prefix 길이와 연속 key를 모든 output에 강제한다. Tuple arity·dtype·device와 full/predicted output wrapping을 원본대로 유지한다. conditional/unconditional context state를 합치지 않는다.

8. 리스크 · 한계

실제 workload에서 retained history가 도움되는지, contamination이 해로운지, burst가 낫는지는 모두 unknown이다. Old prefix는 같은 semantic epoch 안에서는 유효한 정보일 수 있다. 오래됐다는 이유만으로 corruption이라고 부르지 않는다. 반대로 discarded 고차 factors를 새 lower-order factors에 임의 접합하면 기준 시점이 섞인다. 이 동작은 admissible retention action이 아니다. S2에 전달하는 것은 stock recurrence가 허용하는 상태 전이와 measured 필요 항목이다. Offline shadow-history는 실험 분석용이며 online cost에서 숨기지 않는다. 형식 scope band나 문서 길이·검사 통과는 novelty·impact 점수와 무관하다. T2는 S2 지원 지위를 표현하는 후보 표기다. 보조 진단이 양성이어도 기존 GP correction, fixed schedule, fixed low-order 대비 잔차가 없으면 독립 방법 주장은 지지되지 않는다.

P4 Problem-first · self-check · up/down/sideways trace

Retrospective disclosure: 아래 trace는 기존 P2와 P3 리뷰 후 재구성한 P4 판단이다. 최초 ideation이 problem-first였다는 사후 증거로 꾸미지 않는다. Problem-first: cache policy를 먼저 더하는 대신 source에 실제 남는 history가 미래 prediction을 바꾸는지 질문한다. Self-check: p-r를 extra NFE로 착각하지 않았는가, reset으로 clock를 바꾸지 않았는가, equal count와 equal latency를 섞지 않았는가를 점검했다. Up: 큰 주장은 memory-constrained history retention의 quality/time 선택이다. A4 단독으로 이 주장을 입증하지 않는다. Down: actual factor dictionary, context clock, tuple prefix, full-mask count까지 내려가 개입을 고정한다. Sideways: GP correction, DiCache alignment, BudCache schedule, SenCache sensitivity 및 low-order를 대안 원인으로 둔다. 남은 결정: S2 지원 진단 채택 또는 학습용 negative-result 보존은 사용자 몫이다. 문서 수정만으로 점수를 올리지 않는다.

이 세션이 묻는 것

이 세션 전체가 붙잡고 있는 하나의 질문을 쉬운 말로 적는다. 아이디어마다의 연구 질문(RQ) 원문은 각 idea 화면에 그대로 실려 있다.

그림을 만들 때 남길 계산과 다시 할 계산을 가려내자.

  • S2 RQ-1
  • 쉬운 말로 — 다시 만드는 수고까지 생각해서 기록을 남기면, 같은 메모리와 품질에서 더 빨라질까? S2의 projected 채택 기준은 전체 실행시간 ≥10% 감소이며 measured 결과는 unknown이다. 고정 낮은 차수나 일반 비용 기반 정책이 같은 결과를 내면 복잡한 정책을 만들 이유가 약하다.
  • A4의 선행 질문 — 같은 정확 계산 schedule에서 기록 보존·초기화만 바꿔 후속 예측 차이가 남는가? 효과 방향과 재구성 비용을 먼저 분리하고, 작은 pilot에서 품질의 미세한 차이를 확정하지 않는다.
  • A2의 평가 질문 — 평균 유사도와 속도가 비슷해도 영상의 동작·정체성 실패로 정책 선택이 달라지는가? 원 문서의 assumed 사전 기준은 평균 LPIPS 차이 ≤0.01, latency 차이 ≤5%인 조건에서 실패율 차이 ≥10 percentage points지만, 작은 pilot은 이 차이를 입증하는 단계가 아니다.
  • 첫 통과 조건 — 등록된 hook 수 >0 (assumed smoke 기준)이고 exact/reuse 분기가 모두 호출되는지 사용자가 확인하도록 설계한다. 이어 같은 초기 latent·hook set·schedule의 causal pilot에서 history 효과를 확인하고, 라벨 재판정이 일치하지 않으면 A2의 순위 역전을 해석하지 않는다. 이 문서에서 모델 실행·벤치마크는 수행하지 않았다.

배경 — 왜 이 문제인가

왜 이것이 문제인지, 지금까지 무엇이 부족했는지다.

이미지를 읽는 ViT encoder에서 token이나 layer를 줄여 본 경험은 Transformer 내부를 이해하는 데 도움이 된다. 그러나 반복 생성에서는 같은 network를 여러 번 호출하며 그림을 점차 완성하므로, 앞서 생긴 근사 오차가 뒤의 입력에도 남을 수 있다. Denoising step은 그림을 고치는 반복, network block은 한 호출 안의 깊이, video frame/chunk는 만들어지는 영상 속 시간으로 서로 다른 축이다. Latent와 denoiser의 기본 역할은 아래 Latent Diffusion·DiT 읽기에서 먼저 확인한다.

저장한 중간값으로 계산을 생략하는 cache는 시간을 아낄 수 있지만 GPU 메모리를 차지한다. 이번 자원 전제는 assumed: 사용자 제공 24–32GB급 단일 GPU이며 실제 모델·설정의 fit은 measured unknown이다. 예측에 쓰던 기록을 버리면 메모리는 줄어도 다음 예측에 필요한 기록을 다시 만드는 계산이 생길 수 있어, 저장 비용과 재구성 비용을 함께 따져야 한다. TeaCache·TaylorSeer·CG-Taylor·LightCache가 이미 제공하는 기능을 배우고, 그 뒤에도 남는 문제인지 확인하는 연구다.

처음 하는 사람의 4주

이 주제를 처음 보는 사람이 무엇부터 읽고 무엇을 먼저 돌려 보면 되는지다.

아래는 assumed 학습 순서이며 달력 기한이나 GPU 시간 약속이 아니다. 각 단계의 완료 조건을 충족하면 다음으로 가고, 실패하면 원인을 정리해 범위를 다시 정한다. 실제 실행은 사용자 몫이며 이 안내는 실험 설계다.

  • 1주차 — 코드 읽기: 입력 조건 → 초기 latent → 반복 network → scheduler → decode를 그린다. Denoising step·block·영상 시간을 각각 다른 축으로 표시하고, TeaCache의 reuse와 TaylorSeer의 history prediction을 자기 말로 구별한다.
  • 2주차 — 재현 준비와 등록 smoke: 모델과 공개 baseline의 revision·shape·precision·guidance·offload를 고정하고 초기 latent를 저장하는 계획을 만든다. Default hook 이름이 대상 모듈과 맞는지 검사하고 등록 목록·등록 수·실제 exact/reuse 분기 실행 및 cache-disabled parity를 먼저 확인하도록 한다. GPU fit과 clip runtime은 이때 처음 measured로 채우며, 아직 unknown이다.
  • 3주차 — causal pilot과 quick-check: A4처럼 같은 schedule에서 history retain/clear를 비교하고 local prediction error와 최종 영상을 따로 본다. 예정 refresh가 재구성을 전부 충당하거나 낮은 차수만으로 충분하면 그 음성 결과를 보존한다. A2 평가는 방법명을 가린 실패 라벨과 반복 재판정·불일치 기록을 포함하도록 보완하고, 평균 fidelity·motion·identity를 함께 확인한다.
  • 4주차 — 조건부 확장: history가 실제 메모리·재구성 병목이고 단순 대안 뒤에도 차이가 남을 때만 S2의 동적 정책으로 간다. 동일 estimator의 myopic·일반 비용 기반·재구성 고려 정책을 비교하고, 정책 비용·복사·decode까지 포함한 전체 시간과 peak를 기록하는 설계를 완성한다. 추가 모델이나 큰 설정은 pilot 결과를 본 뒤 결정하며, 개선 방향조차 현재 unknown이다.

기초부터 연구 질문까지

이 자료는 연구 후보를 고르기 위한 설계 문서다. 성능 결과는 아직 없다. 숫자로 적은 합격 기준은 사전 제안이며 측정값이 아니다. 사용 가능한 자원은 교수님이 확인한 24–32GB급 단일 GPU다.

1. 기존 ViT 경험에서 무엇을 가져올까

  • 가져올 것: Transformer block 읽기, attention/MLP 구분, activation 수집, layer별 변화 분석, 실제 실행시간 측정 습관.
  • 새로 배울 것: 생성 모델은 같은 network를 서로 다른 noise level에서 여러 번 실행한다. feature가 비슷해 보여도 작은 오차가 뒤의 sampling 경로에 영향을 준다.
  • 연구 질문의 변화: “어느 layer에서 token을 없애면 좋은가”에서 “어떤 상태를 저장하고, 언제 정확한 계산으로 갱신해야 실제 비용이 줄면서 품질이 유지되는가”로 이동한다.
  • Layer별 분석은 필요할 수 있지만 기여 자체로 확정하지 않는다. 분석 결과가 실제 정책과 재현 가능한 실패 조건을 바꾸는지 확인해야 한다.

2. 생성 과정 한 장

생성 파이프라인 그림은 메인 패널에서 볼 수 있다.

  • Latent는 픽셀보다 작은 내부 표현이다. VAE decoder가 마지막 latent를 픽셀로 바꾼다.
  • DiT는 이 내부 표현의 patch들을 Transformer로 처리하는 denoiser다. VLM 앞단의 vision encoder와 역할이 다르다.
  • Diffusion과 flow matching은 학습 목적·sampling 식이 같지 않다. 둘 다 반복 network 평가가 나타날 수 있다는 공통점만 이용하고, scheduler 식은 실제 모델에 맞춘다.
  • 근거 읽기: Latent Diffusion, DiT, Flow Matching. 모두 이번 세션에서 abs 페이지 실존·내용 확인.

4. 캐시가 빠르게 만드는 이유와 느리게 만드는 이유

  • Full compute는 expensive block을 실행한다. Cache hit는 저장한 값을 읽거나 예측값을 만들고 그 block을 건너뛴다.
  • Cache에는 feature 저장, load/store, 예측용 history, gate 계산, CPU/GPU synchronization 비용이 붙는다.
  • skip ratio는 계산을 생략한 비율이다. speedup은 실제 전체 실행시간의 비율이다. 둘은 같지 않다.
  • Cache 용량은 논리 tensor 크기와 실제 storage 보유량이 다를 수 있다. View는 원본 storage 전체를 붙잡을 수 있다.
  • Model weights, cache states, attention workspace, VAE decode workspace, allocator reservation을 구분해 기록한다.

analytic 식

T_base = T_fixed + T_denoise

T_cache = T_fixed + T_remaining + T_gate + T_predict + T_memory + T_sync

speedup = T_base / T_cache

  • 실제 비중을 모르면 speedup 숫자를 예측하지 않는다.
  • 예시만 보자: denoising 비중 0.80, denoising 시간 절반 감소, 추가 overhead 전체 baseline의 0.05라 가정하면 1/(0.20+0.40+0.05) = 1.54×다. analytic 예시이며 우리 기법 결과가 아니다.
  • 동일 과정에서 denoising 비중이 0.40이라면 같은 가정의 값은 1/(0.60+0.20+0.05)=1.18×다. 전처리와 decode가 커지면 기대 이득이 작아진다.

5. 비슷한 feature가 안전한 feature인가

  • Cosine similarity가 높더라도 작은 중요 영역이나 고주파 세부가 손상될 수 있다.
  • 현재 latent에서 full compute해 얻은 값은 “한 번도 caching하지 않은 trajectory의 같은 step 값”과 같지 않을 수 있다. 이전 step의 근사 오차가 이미 현재 latent에 들어 있기 때문이다.
  • Counterfactual 실험에서는 같은 prompt/seed에서 full trajectory와 cache trajectory를 둘 다 보존한다. Local residual error와 최종 품질을 따로 비교한다.
  • 고정 seed의 PSNR/SSIM/LPIPS는 full-compute 결과와의 유사성을 재는 fidelity 지표다. 그 결과가 좋은 영상이라는 뜻까지 증명하지 않는다.
  • 생성 품질은 prompt 충실도, subject consistency, temporal flickering, motion 등의 분리된 축으로 확인한다. VBench의 dimension 정의를 먼저 읽는다.
  • 정지 영상은 temporal consistency가 좋아 보일 수 있다. Motion이 줄어드는 편법을 잡기 위해 dynamic degree와 prompt의 동작 요구를 함께 확인한다.

7. 실험 난사를 피하는 Build-up

1. 응용의 실패를 한 문장으로 쓴다. 예: 캐시를 켜면 생성은 빨라지지만 목표 메모리에서 해상도를 유지하지 못한다. 이 문장은 아직 검증할 가설이다. 2. 원인을 분해한다. State의 실제 bytes·생존 구간·재사용 횟수와 gate/predict 비용을 기록한다. 3. 가장 단순한 반론을 먼저 실험 설계에 넣는다. cache 수 제한, predictor order 고정, 단순 주기 refresh, 기존 offload, 단계 종료 시 cache release만으로 해결되면 복잡한 정책의 필요성이 약하다. 4. 한 개의 결정적 비교를 정한다. 같은 hardware·quality·memory cap에서 제안과 가장 가까운 기존 기법을 비교한다. 5. 실패하면 가설을 수정한다. 모델·seed·threshold를 결과가 나올 때까지 바꾸지 않는다. 변경 이유와 새 가설을 남긴다.

  • 확장: 성공한 경우에만 다른 모델 family와 workload로 확장한다.

용어

  • DiT — Diffusion Transformer, latent patch를 처리하는 생성 network.
  • VAE — Variational Autoencoder, 픽셀과 latent 사이를 바꾸는 encoder/decoder.
  • CFG — Classifier-Free Guidance, 조건부·무조건부 예측을 조합하는 방식; distilled guidance 모델에서는 구현이 다를 수 있다.
  • Residual — block이 입력에 더하는 변화량; 원본 hidden state 전체와 구분한다.
  • Cache age — 마지막 정확한 계산 이후 지나간 재사용 거리.
  • Fidelity — 기준 출력과 닮은 정도; 주관적 품질과 동일하지 않다.
  • Ablation — 한 요소만 제거하거나 바꿔 효과의 원인을 비교하는 실험.
  • Pareto frontier — 한 지표를 개선하면 다른 지표가 악화되는 대안들의 경계.
  • Calibration — test 전에 설정/예측기를 맞추는 별도 데이터 단계.
  • OOM — Out Of Memory, 필요한 실제 할당이 사용 가능한 메모리를 넘은 상태.

  • 학생의 activation·layer 분석 경험은 재사용할 수 있다. 생성 모델에서는 여기에 denoising step과 history state의 시간적 의존성이 더해진다.
  • ‘비슷한 feature를 cache한다’, ‘중요한 step을 찾는다’, ‘오차가 커지면 refresh한다’는 broad mechanism은 이미 많은 연구가 다룬다. TeaCache, TaylorSeer, EpaCache, GP-Refiner가 중요한 비교군이다.
  • 메모리도 빈 영역은 아니다. CG-Taylor, FreqCa, LightCache, Xema를 이겨야 할 범위를 먼저 정한다.
  • 이번 차별화 가설은 특정 layer 번호가 아니라 predictor state가 의존성을 가진다는 점과 회수 이후의 재구성 비용에 있다. 그 비용이 실제로 중요하지 않으면 더 큰 기법을 만들지 않는다.
